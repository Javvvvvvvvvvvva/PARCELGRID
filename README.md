# PARCELGRID

주소 검색이나 지도에서 부지를 선택해 필지 현황, 계획 매스, 사업성, 전문가 인계, 예비 보고서까지 연결하는 **한국 저층 개발 의사결정 도구**입니다.

PARCELGRID는 공공데이터와 사용자 가정, 알고리즘 추천을 분리해 개발 초기 의사결정을 설명 가능하게 만드는 로컬 우선 플랫폼입니다. 서울 소규모 주거의 **예비 면적 프로그램·세대 구성·주차·손익 비교를 자동화**하며, 실시설계나 허가 승인을 자동 확정하지 않습니다. 현재 회귀 기준 프로젝트는 **서울 도봉구 쌍문동 281-23**이며, 화면·사업성·SketchUp(COLLADA DAE)·CAD(DXF)가 같은 대표 계획안과 Geometry Hash를 사용합니다.

> 현재 구현 기준은 [PROJECT_MEMORY.md](PROJECT_MEMORY.md)와 [최신 master 통합 결정](docs/MASTER-INTEGRATION-2026-11-10.md)입니다. 지도·실내·외벽 기능을 통합하되 저장은 조직별 서버 Workspace를 유지합니다. 이전 IndexedDB 문서는 현행 인증·저장 정책을 대체하지 않습니다.

## 제품 원칙

- **사실과 추천을 분리합니다.** 공공 원문, 사용자 입력, 알고리즘 추천, 참고값을 같은 확정값처럼 표시하지 않습니다.
- **모든 주요 숫자에 근거를 연결합니다.** 출처, 확인 상태, 신뢰도와 수정 이력을 함께 다룹니다.
- **사용자 값을 자동으로 덮어쓰지 않습니다.** 추천안은 비교·복제 후 사용자가 확정합니다.
- **하나의 형상을 끝까지 유지합니다.** 계획 스튜디오, 3D, 사업성, DAE, DXF, 인계와 보고서가 같은 대표안을 사용합니다.
- **법적 최대와 실제 가능안을 구분합니다.** 법적 상한 참고안은 산술 FAR 적층이 아니라 공간 검증을 통과한 비교용 형상입니다.

| 영역 | 현재 기능 |

| 부지 입력 | 주소 자동완성, PNU, 지적 경계, 용도지역, 도로·주변 건물, 건축물대장, 실거래 조회 |
| 현황 분석 | 출처·신뢰도 표시, 기존 건축물과 접도 조건, 주변 거래·역세권·리스크 요약 |

| Plan Studio | 실행 가능 후보 생성, 건축 타당성안·개략 손익안·법적 상한 참고안 비교, 빠른 계획·정밀 편집 |
| 3D·형상 검증 | 층별 매스, 배치·회전, 도로 침범, 층 지지, 면적 오차, 주차와 Geometry Hash 검증 |
| 내부 구획 | 독립 템플릿 후보, 2D 편집·수동 문 연결, 공간 관계, 3D 구획, 경계·겹침·코어 연결 검사, 명시적 사업성 반영 |

| 보고서 | 현황·계획·사업성·리스크·근거·승인·AI 외장 콘셉트를 포함한 A4 인쇄형 결과 |
| 내보내기 | SketchUp용 COLLADA DAE, AutoCAD 호환 R2000 ASCII DXF, 메타데이터·안내문 |

| 내부 구획 인계 | 별도 개념 DXF ZIP과 Rhino 3DM, 미터·층·원점·레이어·Geometry Hash. 벽체 상세/허가도면은 미포함 |

## 사용자 흐름

| 단계 | 경로 | 주요 결과 |
|---|---|---|
| 0. 부지 선택 | `/projects/new` | 조직 프로젝트 목록(`/`)에서 새 부지 → 주소 또는 지도 선택 → 경계·면적 확인 |
| 1. 현황 확인 | `/projects/[projectId]/status` | 취득대금 없이 요약 확인, 상세 대장·3D·도로는 펼쳐보기 |
| 2. 계획 스튜디오 | `/projects/[projectId]/envelope` | 취득대금 입력 후 추천 비교·층별 프로그램·배치·주차·3D·대표안 확정 |
| 3. 사업성 | `/projects/[projectId]` | 인수가·공사비·금융비·매출·수익성 재계산 |
| 4. 전문가 인계 | `/projects/[projectId]/handoff` | 근거·승인 기록과 로컬 인계 패키지 |
| 5. 보고서 | `/projects/[projectId]/report` | 인쇄 가능한 통합 예비 검토 보고서 |

현황 단계에서는 실거래 조회나 재무 계산을 실행하지 않습니다. 기존 계획 스튜디오에는 손익 비교가 포함되므로 계획 검토로 넘어갈 때 총 취득대금과 취득 예정일을 받습니다. 주변 토지 거래 분포는 이 단계에서 사용자가 펼칠 때만 조회하며, 가격을 자동 입력하지 않습니다.

보조 화면으로 거래사례 비교(`/comps`), 가격 검토(`/price-review`), 시나리오 비교(`/comparison`), 계산 수정 근거(`/overrides`), 실행 환경 점검(`/system/readiness`)을 제공합니다.

## 빠른 시작

### 요구 환경

- Node.js `24.x`
- pnpm `11.1.0`
- 최신 Chrome 또는 Chromium 계열 브라우저

### 설치 및 실행

```bash
git clone <repository-url>
cd PARCELGRID
corepack enable
corepack prepare pnpm@11.1.0 --activate
pnpm install --frozen-lockfile
cp .env.example .env.local
pnpm dev
```

[http://localhost:3000](http://localhost:3000)을 열고 `서울 도봉구 쌍문동 281-23`을 회귀 데모 주소로 사용할 수 있습니다. PostgreSQL과 외부 API 키가 없어도 로컬 시드와 서버의 versioned Workspace 저장소를 이용한 단일 프로세스 흐름은 동작합니다. VWorld가 VPN이나 네트워크 정책으로 차단된 환경에서는 `VWORLD_ENABLED=false`로 두면 외부 요청을 건너뛰고 Kakao 주소·MOLIT 건축물대장·사용자 토지 정보·선택 GeoJSON 경계로 신규 부지 등록을 계속합니다.

실행 준비 상태는 [http://localhost:3000/system/readiness](http://localhost:3000/system/readiness) 또는 다음 API로 확인합니다. 비밀 키 원문은 응답에 포함되지 않습니다.

```bash
curl http://localhost:3000/api/system/readiness
```

## 환경변수

실제 값은 `.env.local`에만 저장하고 Git에 커밋하지 않습니다. 전체 기본값과 주석은 [.env.example](.env.example)을 기준으로 합니다.

| 변수 | 필요도 | 용도 |
|---|---|---|
| `DATABASE_URL` | 로컬 선택·운영 필수 | PostgreSQL 영구 저장, 활성 조직 멤버십과 DB 불변 감사 원장 |
| `KAKAO_REST_API_KEY` | 실제 주소 조회 | 주소 검색, 좌표와 거리 계산 |
| `NEXT_PUBLIC_KAKAO_JS_KEY` | 선택 | 브라우저 카카오 지도 표시 |
| `VWORLD_ENABLED` | 선택 | `false`이면 VWorld 요청을 보내지 않고 수동 부지 등록으로 전환 |
| `VWORLD_API_KEY` | 실제 필지 조회 | 지적 경계, 용도지역, 도로와 주변 건물 |
| `VWORLD_API_DOMAIN` | V월드 사용 시 | V월드에 등록된 호출 도메인. 로컬 기본값은 `http://localhost:3000` |
| `MOLIT_SERVICE_KEY` | 실제 원문 조회 | 건축물대장과 실거래 공공데이터 |
| `OPENAI_API_KEY` | 선택 | 기준 이미지 기반 AI 외장 콘셉트 렌더 |
| `SITE_ACCESS_ACCOUNTS_JSON` | 공유 서버 | UUID 사용자·조직, 조직 역할과 전문가 자격을 가진 개별 접근 계정 |
| `SITE_ACCESS_SESSION_SECRET` | 공유 서버 | 역할 세션용 HMAC 서명 비밀값. 운영 모드는 별도 32자 이상 |
| `SITE_ACCESS_PASSWORD` | 로컬 미리보기만 | 사용자 분리가 없는 구형 단일 워크스페이스 비밀번호 |
| `AUDIT_LEDGER_STORAGE_DIR` | 로컬 선택 | PostgreSQL이 없을 때 쓰는 단일 프로세스 append-only 감사 원장 |
| `PROJECT_WORKSPACE_STORAGE_DIR` | 로컬 선택 | PostgreSQL이 없을 때 쓰는 조직별 불변 프로젝트 revision 저장소 |

AI 렌더 모델·저장 경로·호출 제한과 원문 저장 경로는 `OPENAI_IMAGE_MODEL`, `CONCEPT_RENDER_STORAGE_DIR`, `CONCEPT_RENDER_DAILY_LIMIT`, `SOURCE_DOCUMENT_STORAGE_DIR`로 조정합니다.

## Plan Studio 비교 계약

### 소규모 주거 자동화 1차 (2026-10-19)

- 개발 목표: 일반인은 자동 후보의 조건·손익·탈락 이유를 비교하고, 전문가는 후보를 복사해 세대별 면적·비용·단가 근거를 수정하는 공통 계획 모델을 사용합니다.
- 서울, 대지 330㎡ 이하, 규칙 적용일 2026-09-08 이후의 입력에서 일반 다세대 후보를 탐색합니다. 주거 4개 층 이내, 단일·혼합 평형, 지상·필로티 주차를 비교합니다. 모든 설계의 최적해를 보장하는 탐색은 아닙니다.
- 각 세대의 전용면적과 공용부를 분리합니다. 혼합 평형 주차는 세대별 기준을 합산하고, 구형 집계 면적은 균등 분할 가정으로 표시합니다. 도시형 생활주택과 일반 다세대의 주차·용도 분류를 혼용하지 않습니다.
- 공용부는 매각 매출에서 제외합니다. 추가 세대의 공용부 손실과 주방·욕실·배관 순증 비용을 반영하며, 기본값은 견적이 아닌 내부 가정입니다. 기본 ㎡ 공사비와의 중복 포함 여부를 확인해야 합니다.
- 평형별 최종 단가를 입력할 수 있으며 구간·근거를 보존합니다. 미입력 구간은 공통 주거 단가를 사용하고, 근거 없는 소형 프리미엄은 자동 부여하지 않습니다. 동일 매각 면적과 가중 단가가 Stage 3에 전달됩니다.
- 비교표는 구성별 예비 후보, 주차 필요/2D 배치 대수, 매출·비용·손익, 매각 -10%/공사 +15% 민감도, 미충족 항목을 표시합니다. 후보 복사는 기존 수동 계획을 덮어쓰지 않습니다.
- 경계가 없으면 조건부 면적 비교만 허용하고 3D 법적 상한·배치 적격안은 만들지 않습니다. 실내 평면·기둥·차량 회전궤적·진출입 허가가 미검증인 새 면적 프로그램은 대표안 확정으로 자동 승격되지 않습니다.
- 실내 구획·차량 후보 궤적의 예비 검사는 아래 3차 범위에 포함됩니다. 근거 문서와 연결된 상세 설계·전문가 승인 전환은 후속 범위이며 이미지 생성은 계산·허가 근거를 대신하지 않습니다.

회귀 기준: `src/tests/dwelling-program.test.ts`의 122㎡/200%·250%/4·6·8세대와 좁은·비정형 테스트 경계입니다. 예전 데모의 가상 경계는 공식 지적 경계가 아닙니다. 브라우저 검증 자료는 `artifacts/dwelling-automation-2026-10-19/`에 기록합니다.

### 평형별 거래 근거 자동화 2차 (2026-10-20 한국 기준)

- [국토부 연립·다세대 매매 API](https://www.data.go.kr/data/15126467/openapi.do)를 신규 프로젝트 수집에 추가했습니다. 기존 프로젝트는 Plan Studio의 세대 구성 편집에서 공식 자료를 다시 조회할 수 있습니다. VWorld는 필요하지 않으며 `MOLIT_SERVICE_KEY`의 해당 서비스 이용 권한이 필요합니다.
- 전용면적 기준 연립·다세대와 연면적 기준 단독·다가구 통매각을 구분합니다. XML 구조를 검증하고 취소 필드 누락/공란, 계약·등기일, 거래구분, 매수·매도자, 층·연식, 원본 수집시각을 보존합니다. 같은 공개 식별값의 취소 신고는 응답 순서와 관계없이 우선합니다.
- 연립·다세대 자료는 `ProjectComputed.dwellingMarket`에 별도 보관해 기존 토지·통매각 비교 및 가격 검토 후보와 섞이지 않습니다. Workspace 저장·계획 재계산·Stage 3 확정에서도 이 자료를 유지합니다.
- 내부 비교 정책 `dwelling-market-2026.1`: 동일 시군구·법정동, 최근 12개 달, 거래연도 기준 준공 5년 이내, 2~5층, 개인 매수·개인/법인 매도·중개거래·등기일 확인. 목표 전용면적의 ±10%(최소 2㎡, 최대 5㎡)만 비교하며, 주소별 단가 중앙값을 다시 중앙값으로 집계합니다. 법인 매도에는 최초 분양도 포함될 수 있어 개별 검토가 필요합니다. 이 필터는 법정 기준이나 감정평가 모델이 아닙니다.
- 서로 다른 주소 3곳 미만, 취소 상태 미확인, 불완전한 월 수집, 원본 수집 후 7일 경과, 계획 면적 기준·층 불일치에서는 관측 단가 채택을 차단합니다. 같은 동을 1km 반경으로 표시하지 않습니다. 관측 최저~최고는 표본 범위이며 신뢰구간·분양가 예측이 아닙니다.
- 조회만으로 가격은 변경되지 않습니다. 사용자가 채택하면 기존 평형 단가를 교체하고 해당 계획의 정확한 전용면적에 한정된 가정으로 저장합니다. 미지원 평형은 공통 단가 가정을 유지합니다. 채택 당시 거래·조회 근거를 복제 보존하며 수동 수정은 관측 근거 표시를 해제합니다. 계획 면적·층·대상 프로젝트가 바뀌면 해당 관측 단가를 자동 재사용하지 않습니다.
- Stage 2와 Stage 3는 동일 매각 면적·가중 최종 단가를 공유합니다. 민감도 분석은 채택한 수익 계약을 조정하며 거래 원본을 수정하지 않습니다. 관측 채택은 항상 `user-input`이며 전문가 확인·허가·미래 분양가 확정으로 승격되지 않습니다. 기존 통매각 기반 공통 단가는 여전히 예비 가정이므로 미지원 평형의 확정 단가로 해석하면 안 됩니다.

쌍문동 실제 수집 및 데스크톱/모바일 검증 산출물: `artifacts/dwelling-market-2026-10-20/`. `official-live-response.json`은 키가 없는 실제 조회 결과이고, 파일명에 `synthetic`이 있는 화면은 적용/수정 동작만 검증한 합성 표본입니다. 이 자료를 제품 기본 단가로 고정하지 않습니다.

- 자동 시나리오는 법정 건축물 용도코드가 확정되고 해당 층수·면적·가구수 조건을 통과한 경우에만 생성합니다.

## 로컬 데이터와 보안

- 원문 PDF·Excel·CSV는 조직별 격리 경로 아래 `.parcelgrid-data/source-documents`에, AI 결과는 `.parcelgrid-data/concept-renders`에 저장되며 Git에서 제외됩니다.
- 로컬 개발에서는 명시적인 로컬 소유자 세션을 사용합니다. 공유 서버에서는 사용자별 `SITE_ACCESS_ACCOUNTS_JSON`, 전용 세션 비밀값과 PostgreSQL 멤버십이 필요합니다.
- PostgreSQL이 없으면 `.parcelgrid-data/project-workspaces`의 조직별 불변 revision과 로컬 감사 원장을 사용합니다. 같은 Node 서버에서는 브라우저를 닫아도 다시 열 수 있지만, 여러 서버 인스턴스나 다른 PC 서버 사이에는 자동 동기화되지 않습니다.
- PostgreSQL 운영 배포는 `pnpm db:migrate`로 Workspace와 감사 원장의 UPDATE·DELETE·TRUNCATE 차단 trigger를 먼저 적용해야 합니다.
- 자동저장은 revision을 비교하며, 충돌 시 다른 사용자의 값을 덮어쓰지 않습니다. 화면에서 로컬 JSON 사본을 내보낸 뒤 서버 최신본을 다시 열어 수동으로 대사합니다.
- 인계 패키지는 계획·Geometry·사업성 근거를 옮기지만 원문 PDF·Excel, AI 이미지와 서버 권한 승인은 포함하지 않습니다. 대상 PC에서 원문을 다시 연결하고 같은 조직의 서버 감사 원장에서 승인을 불러와야 합니다.
- 내장 계정 세션은 역할 분리형 배포 게이트이지 법적 전자서명이나 기업용 SSO/MFA가 아닙니다. 다중 인스턴스·고객 운영에는 외부 IdP, 공유 rate limiter, 관리형 파일 저장소가 필요합니다.

## 검증

지도·주소 진입 흐름은 프로덕션 빌드 후 `pnpm test:browser:intake`로 확인합니다. 좌표를 투영하는 합성 지도 SDK·API 응답으로 도형의 구멍·복수 영역, 레이어 전환, 이전 선택 응답 폐기, 부분 실패를 검사합니다. 실제 지도 타일과 승인된 공공 API의 정확성 검증은 별도로 필요합니다. [지도 선택 가이드](docs/KR-MAP-INTAKE.md)에 범위와 실제 확인 절차를 기록했습니다.

저장·복구는 `pnpm test:browser:storage`로 실제 Chromium IndexedDB의 재접속·저장 실패·두 탭 충돌·복구·모바일 UI를 검사합니다. 마이그레이션 중단·프로젝트 격리·동시 저장은 fake-indexeddb 단위 테스트로 검증합니다. [저장 계약과 사용법](docs/KR-WORKSPACE-STORAGE.md)을 참고하세요.

건축물대장 근거의 별도 브라우저 검사는 프로덕션 빌드 후 `pnpm test:browser:registry`로 실행합니다. 실제 API 승인 계정 검증은 합성 응답 검사와 별개이며 [가이드](docs/KR-BUILDING-EVIDENCE.md)에 남은 조건을 기록합니다.

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build

# 전체 검증
pnpm verify
```

GitHub Actions는 lint, 타입 검사, 전체 Vitest, production build를 실행합니다. 프로젝트의 출시 기준은 로컬 우선이며, 호스팅 플랫폼의 PR 미리보기는 보조 확인 수단으로만 사용합니다.

새 내부 구획은 Plan Studio의 **내부 구획 열기**에서 사용합니다. 외곽·구획·사업성 입력이 달라지면 대표안 확정 전에 면적을 다시 반영해야 합니다. 사용 조건과 전체 리소스의 도입 상태는 [49개 리소스·10개 데이터 축](docs/KR-UPGRADE-RESOURCES-2026-09-28.md)을 참고하세요. `pnpm notices:generate`는 설치한 production 의존성의 [오픈소스 고지](public/third-party-notices.txt)를 갱신합니다.

자동 검증이 통과해도 다음 항목은 실제 프로그램과 브라우저에서 확인해야 합니다.

- 새 브라우저에서 주소 검색부터 보고서까지 전체 흐름
- DAE를 SketchUp에서 열어 원점·축·층·주차 확인
- DXF를 AutoCAD 호환 프로그램에서 열어 meter 단위와 `PG_*` 레이어 확인
- 보고서 A4 인쇄 미리보기의 잘림·겹침
- 실제 API 키를 사용한 외부 API 성공·실패 안내
- 다른 PC에서 인계 패키지 가져오기와 원문 재연결

Plan Studio의 **외장재·Plan DNA**에서 층/외벽별 재료, 개구부 면적, 공유벽 여부와 재료별 단가를 입력할 수 있습니다. 검증된 형상의 수직 외벽 수량과 재료비 차액을 같은 버전으로 Stage 3·보고서에 전달합니다. 미입력 단가와 경계 미확정 면적은 따로 표시합니다. 실제 시공 수량과 창호 상세는 별도 검토가 필요합니다. 사용법·라이브러리 비교·한계는 [KR-U3 외벽 수량 계약](docs/KR-FACADE-QUANTITIES.md)을 참고하세요. `pnpm test:browser:facade`로 편집·저장·복구를 확인합니다.

## 협업 규칙

- 변경은 기능 브랜치와 Pull Request로 합칩니다.
- `.env.local`, `.parcelgrid-data`, 실제 고객 원문과 비밀 키는 커밋하지 않습니다.
- 형상·재무 로직을 바꾸면 관련 회귀 테스트와 사용자에게 보이는 근거 문구를 함께 갱신합니다.
- 합치기 전 `pnpm verify`를 통과해야 합니다.
- 세부 규칙은 [CONTRIBUTING.md](CONTRIBUTING.md)를 따릅니다.

## 면책

PARCELGRID 결과는 AI·공공데이터 기반의 초기 콘셉트 검토입니다. 건축설계도서, 인허가 도면, 측량성과도, 시공도, 감정평가서, 금융 약정 또는 공사비 견적서가 아닙니다. 매입·설계·인허가·대출·세무 판단 전 각 분야 전문가가 원문과 현장을 확인하고 승인해야 합니다.
