# Zoning Use Screening Contract 2026.1

> 이 계약은 [Zoning Use Screening Contract 2026.2](ZONING-USE-SCREENING-2026.2.md)로 대체되었다. 2026.2는 상품명과 건축법상 세부 용도를 분리하고 관할·기준일·정량조건을 자동 생성 게이트에 추가한다.

## 목적

`zoning-use-screening-2026.1`은 자동 생성 시나리오의 용도지역과 건축물 용도 조합을 보수적으로 사전 선별한다. 이 결과는 비교 후보를 만들 근거이지 건축허가 가능 판정, 법률 자문 또는 관할 행정청 협의 결과가 아니다.

국가 기준은 2026-09-08 현재 시행 중인 [국토의 계획 및 이용에 관한 법률 시행령 제71조](https://law.go.kr/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=1000616244)와 연결 별표 2~22를 기준으로 한다. 제71조는 용도지역별 제한을 별표로 나누며, 실제 허용 범위 중 상당 부분은 도시·군계획조례에 위임한다. 서울 입력에는 [서울특별시 도시계획 조례 현행 검색](https://www.law.go.kr/ordinSc.do?menuId=3&query=%EC%84%9C%EC%9A%B8%ED%8A%B9%EB%B3%84%EC%8B%9C%20%EB%8F%84%EC%8B%9C%EA%B3%84%ED%9A%8D%20%EC%A1%B0%EB%A1%80)을 함께 기록한다.

## 상태 계약

| 상태 | 의미 | 자동 후보 생성 |
|---|---|---:|
| `national-reference` | 국가 기준의 용도 범주와 대응하지만 조례·중첩 규제 확인 전 | 허용 |
| `local-ordinance-review` | 조례 위임, 규모 조건 또는 제품의 법정 용도 매핑 확인 필요 | 경고와 함께 허용 |
| `unsupported-auto` | 현재 규칙 버전에 자동 생성 근거가 없음 | 금지 |
| `unknown` | 세부 용도지역을 분류하지 못함 | 금지 |

모든 상태의 `decisionGrade`는 `false`다. `national-reference`도 최종 합법 판정이 아니다.

## 현재 후보 범위

| 용도지역 | 자동 비교 후보 |
|---|---|
| 제1종전용주거 | 단독주택 매각, 다가구 매각·임대형. 다가구는 조례 검토 |
| 제2종전용주거 | 단독주택 매각, 다가구 매각·임대형 |
| 제1종일반주거 | 단독주택 매각, 다가구 매각·임대형, 근린생활 임대형 조례 검토 |
| 제2·3종일반주거 | 저층 후보와 부지 규모에 따른 도시형생활주택 매각·임대형 |
| 준주거 | 도시형생활주택, 업무시설, 오피스텔, 근린생활의 검토 후보 |
| 중심·일반·근린상업 | 업무시설, 오피스텔, 근린생활 후보 |
| 유통상업 | 유통·근린생활 임대형 검토 후보 |
| 준공업 | 일반 업무시설·근린생활 임대형 검토 후보 |

전용·일반공업, 녹지, 관리, 농림, 자연환경보전 및 세분되지 않은 `주거지역`·`도시지역`은 현재 자동 후보를 만들지 않는다. 산업시설을 일반 업무시설로 바꾸거나 미분류 지역에 오피스텔을 넣는 추측보다 사용자에게 원문 확인을 요구하는 쪽을 선택한다.

## 전략 계약

- `sale-exit`: 주거 분양 또는 단독·다가구 통매각. 임대 풀을 섞지 않는다.
- `stabilized-lease-exit`: 임대 안정화 NOI를 Cap rate로 환산해 종료 시점에 매각한다. 장기 보유 전략이나 실제 take-out 대출은 아니다.
- 같은 건축물 용도의 매각형과 임대형은 서로 다른 시나리오 ID, 용도 믹스와 가격 가정을 가진다.
- 코리빙은 운영 명칭만으로 건축법상 주택·숙박·기숙사 용도를 확정할 수 없어 전 용도지역에서 자동 생성을 중단한다.

## 필수 후속 확인

1. 관할 도시·군계획조례의 용도, 규모, 층수와 접도 조건
2. 지구단위계획, 용도지구·구역, 경관·고도 등 중첩 규제
3. 건축법 시행령 별표 1의 실제 세부 용도 분류
4. 주택 유형·세대수·면적, 주차, 피난, 소방과 장애인 편의 기준
5. 인허가권자 또는 건축사의 프로젝트별 확인

## 실패 방식

세부 용도지역을 분류하지 못하거나 현재 지원하지 않는 지역이면 생성 결과는 빈 배열이다. 동적 프로젝트 API는 이를 `422 NO_ELIGIBLE_SCENARIO`로 반환하며 임의의 수익 시나리오를 계산하지 않는다.
