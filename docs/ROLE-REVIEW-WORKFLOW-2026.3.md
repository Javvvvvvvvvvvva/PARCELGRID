# PARCELGRID 역할별 검토 워크플로 2026.3

기준일: 2026-09-09  
모델: `server-review-workflow-2026.2`

## 서버 권위

검토 상태는 브라우저 입력 JSON이 아니라 조직 감사 원장의 이벤트에서 다시
도출한다. 사용자 이름·소속·조직 역할·서버 시각은 서명 세션과 활성 DB 멤버십을
기준으로 기록한다. 브라우저는 검토 분야, 원하는 다음 상태, 근거 참조, 의견과
확인란만 제출한다.

## 상태와 책임

`미요청 -> 요청 -> 검토 중 -> 승인 또는 수정 요청`만 허용한다. 승인 뒤 새
Snapshot을 재요청할 수 있다. 요청은 `owner/admin/analyst`, 검토는
`owner/admin/reviewer` 중 해당 분야 전문가 자격을 가진 계정만 수행한다.

요청자와 검토자는 같은 Snapshot에서 달라야 한다. 검토 시작 이벤트가 담당자를
고정하고 그 담당자만 최종 결정을 내린다. 승인에는 근거 참조, 의견, 계산·Geometry
Snapshot 확인, 분야 원문 확인, 예비 타당성 한계 확인이 모두 필요하다.

## 감사와 보고서

각 전이는 조직별 SHA-256 감사 체인에 기록되고 낙관적 이전 해시 충돌을 검사한다.
검토 요청 전 현재 Stage 3 계산·Geometry 식별자·원문·가격 검증·세무 계약 본문을
서버에 봉인해야 한다. 상태 이벤트는 64자리 Snapshot SHA-256과 실제 봉인 이벤트의
감사 해시를 함께 기록한다. 체인 검증이 실패하거나 현재 로컬 계산의 SHA-256과
봉인·승인 기록이 다르면 최종 보고서를 잠근다.

## 현재 경계

2026.3은 승인 주체, 권한, 대상 본문과 상태 이력을 서버에서 강제한다. 내장 계정은
법적 전자서명이 아니며 외부 IdP·MFA·인증서 기반 서명은 별도 운영 통합이 필요하다.
로컬 append-only 원장은 여러 프로세스 동시성이나 규제 산업용 WORM 보관을
보장하지 않으므로 공유 운영 승인은 PostgreSQL 불변 트리거를 전제로 한다.
