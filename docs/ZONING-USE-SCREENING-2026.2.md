# Zoning Use Screening Contract 2026.2

## 기준과 목적

`zoning-use-screening-2026.2`는 PARCELGRID의 상품명과 법정 건축물 용도를 분리하고, 정확한 용도코드와 정량조건을 확인한 후보만 자동 비교 공간에 넣는다. 기준일은 **2026-09-09**다.

- [국토의 계획 및 이용에 관한 법률 시행령 제71조 및 별표 2~22](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=287269), 시행 2026-07-01
- [건축법 시행령 별표 1 용도별 건축물의 종류](https://law.go.kr/LSW/flDownload.do?bylClsCd=110201&flSeq=155803643), 현행 시행령에서 확인
- [주택법 시행령 제10조 도시형 생활주택](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1030114713), 시행 2026-09-08
- [서울특별시 도시계획 조례](https://www.law.go.kr/LSW/ordinInfoP.do?ordinId=2000719), 시행 2026-07-13

이 결과는 후보 생성 허용 여부다. 지구단위계획, 용도지구·구역, 정비계획, 경관·고도, 접도, 주차, 일조, 피난·소방과 허가권자 판단까지 확인한 건축허가 가능 판정이 아니다. 따라서 모든 결과의 `decisionGrade`는 `false`다.

## 상품과 법정 용도

`building-use-catalog-2026.1`은 상품명을 건축법 시행령 별표 1 코드로 매핑한다.

| 상품 | 자동 후보의 법정 용도 | 코드 | 처리 |
|---|---|---|---|
| 단독주택 | 단독주택 | `BA-A1-1-A` | 정확 매핑 |
| 다가구 | 다가구주택 | `BA-A1-1-C` | 정확 매핑 후 층·면적·가구수 검사 |
| 도시형 생활주택 | 아파트형 주택 | `BA-A1-2-A` + `HA-ED-A10-1-1` | 자동 후보가 세부형을 명시 |
| 소매시설 | 제1종 근린생활시설 중 일용품 소매점 | `BA-A1-3-A` | 자동 후보가 업종 범위를 명시 |
| 업무시설 | 일반업무시설 | `BA-A1-14-B-1` | 면적 구분 검사 |
| 오피스텔 | 업무시설 중 오피스텔 | `BA-A1-14-B-2` | 정확 매핑 |
| 코리빙 | 다중주택·임대형기숙사·다중생활시설 가능 | 복수 | 운영명만으로 확정하지 않고 중단 |

일반 `retail` 입력과 `urban-housing` 입력은 세부코드가 없으면 각각 `building-use-input-required`다. 자동 생성기는 상품명을 바꿔 해석하지 않고, `일용품 소매점`과 `아파트형 도시형 생활주택`을 명시적으로 선택한다.

## 정량조건

| 법정 용도 | 현재 자동 검사 |
|---|---|
| 다가구주택 | 주택 사용층 3개 이하, 주택 용도 바닥면적 660㎡ 이하, 19가구 이하 |
| 다중주택 | 주택 사용층 3개 이하, 주택 용도 바닥면적 660㎡ 이하 |
| 아파트 | 주택 사용층 5개 이상 |
| 연립주택 | 기본 분류에서 주택 사용층 4개 이하, 동별 주택 바닥면적 660㎡ 초과 |
| 다세대주택 | 기본 분류에서 주택 사용층 4개 이하, 동별 주택 바닥면적 660㎡ 이하 |
| 일용품 소매점 | 같은 건축물의 해당 용도 바닥면적 1,000㎡ 미만 |
| 일반업무시설 | 근린생활시설 사무소가 아닌 500㎡ 이상 구간 |
| 임대형기숙사 | 임대 목적 실 20실 이상. 사업자·공동취사 요건은 수동 확인 |

필수 수치가 없으면 `condition-input-required`, 상한·하한을 벗어나면 `condition-failed`로 자동 생성을 막는다. 제1종일반주거지역의 4층 상한과 입력 용도지역명에 표시된 `제2종일반주거지역(7층 이하)`도 후보 층수에 적용한다.

다가구 기본 프로그램은 종전 지상 4층에서 3층으로 수정했다. 자동 후보의 FAR는 `건폐율 × 지상층수`를 넘지 않게 낮추며, 큰 부지에서 다가구 주택면적이 660㎡를 넘으면 다가구 수익안 자체를 제거한다.

## 관할 범위

| 범위 | 동작 |
|---|---|
| 국가 별표의 직접 허용 범주 | 정확한 코드와 정량조건 통과 시 `national-reference` 후보 생성 |
| 서울 조례에 위임된 현재 지원 조합 | `seoul-ordinance-reference`로 후보 생성 |
| 서울의 허용·금지표 추가 검토가 필요한 조합 | `local-ordinance-review` 경고와 함께 예비 후보 생성 |
| 서울 외 조례 의존 조합 | 관할 조례 스냅샷이 없으므로 자동 생성 중단 |
| 미분류 용도지역·미지원 조합 | `unknown` 또는 `unsupported-auto`로 중단 |

서울 판별은 주소 기준 관할코드 `KR-11`로 기록한다. 현재 통합 규칙 스냅샷은 2026-09-08 이후 분석에만 적용한다. 그 이전 기준일은 과거 법령을 현재 규칙으로 소급하지 않고 `source-date-uncovered`로 중단한다.

## 자동 후보의 단일 용도 원칙

종전 오피스텔과 업무시설 기본안에는 근린생활시설 비율이 암묵적으로 섞여 있었다. 2026.2 자동 후보는 오피스텔 또는 일반업무시설 한 용도로 만들고, 근린생활시설을 넣으려면 별도 세부코드와 면적을 가진 계획안에서 검토한다. 이로써 하나의 용도 선별 결과가 확인하지 않은 복합 용도까지 대신 승인하는 문제를 제거한다.

## 실패 방식

- 자동 후보가 모두 탈락하면 동적 프로젝트 API는 기존 계약대로 `422 NO_ELIGIBLE_SCENARIO`를 반환한다.
- 조례 검토 경고는 `reviewItems`, 법정 용도와 조건 결과는 `legalUse`와 `conditionAssessment`, 적용 관할과 기준일은 `jurisdictionCode`와 `asOf`에 보존한다.
- `national-reference`와 `seoul-ordinance-reference`도 전문가·허가권자 확인 전에는 법적 확정값으로 표시하지 않는다.
