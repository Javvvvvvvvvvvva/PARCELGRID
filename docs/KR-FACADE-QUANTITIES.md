# 한국판 외벽 수량·면별 재료·비용 계약 (KR-U3)

기준일: 2026-10-08. 한국 PARCELGRID 원본의 계획 수량 개선이며 실측 물량·시공 상세·공인 견적을 제공하지 않는다.

## 변경 전과 후

| 항목 | 이전 | 현재 |
|---|---|---|
| 자동 수량 | 층 면적의 정사각형 환산 둘레 × 높이 | 기존 검증 Geometry의 각 외곽 변 길이 × 실제 높이 |
| 개구부 | 전체 창호 비율 공제 | 면별 순수 개구부 면적 입력 가능; 해당 면은 비율 대신 직접값을 한 번 공제 |
| 외장재 | 주·보조 색상 혼합 | 면별 재료 지정, 미지정 면은 주·보조 비율에 따른 아래/위 띠로 개념 표시 |
| 질감 | 단색·거칠기·금속성 | 자체 제작 절차적 무늬, UV를 미터 기준으로 반복; 매스 좌표는 동일 |
| 단가 | 전체 조합에 하나의 기준/선택 단가 | 기존 조합 단가 보존 + 재료별 단가 모드, 미입력 부분은 미산정 |
| 인계 | 전역 재료·공사비 증감 | 수량·재료별 표와 버전을 Stage 2, Stage 3, 보고서, Plan DNA에 보존 |

## 수량과 불확실성

- `facade-quantity-2026.1`: 검증된 지상층의 수직 외곽 면만 집계한다. 층간 바닥·지붕·수평 후퇴 테라스를 벽에 합산하지 않는다.
- 같은 외곽선이 위아래 층에 있어도 서로 다른 높이 구간의 벽이므로 각각 한 번 계산한다. 한 층의 내부 구역 공유면은 생성하지 않는다.
- 지하·순수 주차/필로티층은 제외한다. 주차/필로티와 실내가 섞인 층은 구역 경계가 없어 전체 외곽을 미확정으로 보류한다. 기둥·코어 외벽을 면적 비율로 추측하지 않는다.
- 인접 건물 접합 여부는 자동으로 알 수 없다. 기본은 **노출 가정**, 사용자가 노출·공유·미확인을 지정한다. 공유면은 제외, 미확인은 미확정 총면적으로 표시한다.
- 경계 미확정 면적은 **총면적**, 단가 미산정은 확인된 **순면적**이다. 서로 다른 집계이므로 단순 합계하지 않는다.
- 현재 층 Geometry는 단일 외곽 링이다. 중정/내부 링, 파라펫, 발코니 측벽, 창호 위치·프레임·실제 벽 두께는 자동 산출하지 않는다. ㄱ자 등 외곽 오목부는 지원한다.
- 형상 검증 실패나 이전 형상에 묶인 면 설정이 남으면 자동 증감을 보류한다. 잘못된 개구부 면적은 0으로 속이지 않고 해당 면을 미확정으로 돌린다.
- 순면적 직접 입력은 이미 창호가 제외된 값이다. 창호비를 다시 빼지 않는다. 직접 총면적 입력과 면별 지정을 함께 쓰면 수량을 매핑할 수 없어 비용 반영을 보류한다.
- GIS 외곽선 없는 구형 자료는 기존 정사각형 추정을 명시해 호환한다. 이를 형상 기반 수량이라고 표기하지 않는다.

## 재료·가격·버전

`facade-cost-2026.1`의 재료 행별 금액은 `면적 × (선택 원/㎡ − 기준 원/㎡)`이다. Decimal.js로 차액을 계산하고 합산한다. 원→만원은 10,000으로 나눈다. 면적·금액의 표시 반올림을 내부 합계에 재투입하지 않는다.

- 신규 모드의 단가는 각 재료 행에 독립적으로 적용한다. 누락 단가를 다른 재료의 값으로 대체하지 않는다. 확인된 행의 차액만 반영하며 일부 산정 여부·미산정 면적을 표시한다.
- 기존 전체 조합 단가는 혼합 사양 전체의 단가다. 주재료 단가로 재해석하지 않는다. 기존 `0`은 미입력 의미를 유지한다. 신규 재료별 단가는 명시적으로 입력한 0을 허용한다.
- 출처명·기준일 없는 입력을 source-backed로 승격하지 않는다. 문서 URL, 포함/제외 공종·비계·VAT 범위는 별도 필드로 보존하고 출력한다. 출처가 있어도 계획 수량을 실측으로 승격하지 않는다.
- 기본 공사비에 전체 외장비를 다시 더하지 않는다. 기존 Stage 2→3 `materialAdjustmentCostManwon` 경로에 차액만 전달한다. Stage 3의 기존 총 공사비 가정이 동일한 기준 외벽 사양을 포함하는지는 견적 검토가 필요하다.
- 면 식별자는 층 레벨, 실제 변 양끝 좌표(μm 반올림), 높이 구간에 묶인다. 링 시작점·방향이 달라도 같은 면이다. 평면/높이 변경으로 맞지 않는 설정은 다른 면에 자동 전이하지 않는다.
- 재료·단가 변경은 매스 Geometry Hash를 바꾸지 않는다. quantityKey는 수량, costKey는 수량+재료+단가+근거의 변경을 추적한다. 기존 시나리오 버전·검토 스냅샷 키도 변경되어 이전 승인을 현재 값에 재사용하지 않는다.
- 기존 재료가 선택된 저장 사업성에 수량 계약이 없으면 재개 시 계획 입력은 유지하고 대표안·사업성·승인 결과는 재검토 대상으로 돌린다.

## 라이브러리 비교와 채택

| 대안 | 판단 |
|---|---|
| 기존 Three.js 0.184.0 (MIT) | CanvasTexture·BufferGeometry·미터 기반 UV·RepeatWrapping 재사용. 별도 렌더 엔진 추가 없음 |
| 기존 Decimal.js 10.6.0 (MIT) | 단가 차액·합계를 십진 연산으로 계산. 산출 결과는 기존 JSON 숫자 계약 유지 |
| 기존 Turf 7.3.5 (MIT) | 기존 법규·배치·형상 검증을 재사용. 외벽 길이는 이미 미터인 LOCAL_ENU 좌표에서 계산하므로 위경도용 거리 함수를 재적용하지 않음 |
| Flatten.js | 새로운 면적 교차 엔진이 필요한 작업이 아니므로 이번 단계에 중복 도입하지 않음. 내부 평면 KR-U4에서 비교 |
| 외부 PBR 자산 | 이번 단계에는 도입하지 않음. 원본 절차적 패턴으로 물리 반복 크기를 검증. 제품/시공 텍스처로 표기하지 않음 |

확인한 공식 자료: [Three Texture](https://threejs.org/docs/pages/Texture.html), [CanvasTexture](https://threejs.org/docs/pages/CanvasTexture.html), [Decimal API](https://mikemcl.github.io/decimal.js/), [Flatten.js](https://github.com/alexbol99/flatten-js). 기존 배포 라이선스는 `public/third-party-notices.txt`에 포함되어 있다. 의존성/lockfile 추가 없음.

## 검증

수치 회귀: 20×10×3m 벽 총180㎡·창호25% 공제 후135㎡, 둘레36m ㄱ자+둘레16m 상층의 총156㎡, 공유벽·미확인·필로티·잘못된 개구부, 구형 단가 호환, 재료별 부분 비용, 미터 UV, Geometry Hash 불변, Plan DNA/재무 전달 및 승인 키 변경.

브라우저 검사: `pnpm build` 후 `pnpm test:browser:facade`. 외장재·면 선택·개구부·재료별 단가를 편집하고 Plan DNA 합계를 대조한다. 새로고침 후 값/수량키/비용키 복구, 모바일 넘침, 3D 렌더링 오류를 확인한다. 가상 견적을 사용하며 실제 시공비 검증은 아니다.

실제 공급업체 견적, Windows/Safari 실기기, 외부 CAD의 재질 호환, A4 전체 보고서 출력은 별도 확인 대상이다. DAE/DXF/3DM에 이번 절차적 패턴을 내장하지 않으며 기존 매스 좌표·단위·Geometry Hash를 유지한다.
