# 한국판 PARCELGRID 업데이트 실행 계획

작성일: 2026-10-07 (America/Chicago)
코드 기준: `master@3a1f17e17e0eb17d75a056cf6dadd095e08e4da6`
대상: 원본 한국판 `Javvvvvvvvvvvva/PARCELGRID`
상태: KR-U1 주변 지도 레이어 구현 및 자동 검증 완료. 실제 지도·승인 API 확인은 남아 있다. 이후 단계의 신규 패키지는 아직 적용하지 않았다.

사용자 목표는 **라이브러리를 활용해 기능, 사용 편의성, 정확성을 높이는 것**이다. 각 단계는 사용자에게 보이는 개선과 검증 결과를 함께 남긴다. 신규 패키지는 해당 기능에 대한 비교 시험을 통과한 뒤 채택한다.

이 문서가 앞으로의 기능 업데이트 순서를 정한다. [9월 리소스 조사](KR-UPGRADE-RESOURCES-2026-09-28.md)는 당시 49개 후보와 10개 데이터 축의 기록으로 유지한다. [재료·시각화 원칙](PRODUCT-ROADMAP-MATERIAL-COST-AND-AI-VISUAL.md), [기존 출시 검증](PRODUCT-HARDENING-ROADMAP-2026-09-06.md)의 미완료 검증 요건도 유지한다. 미국판 전환은 이 계획의 범위에 포함하지 않는다.

## 2. 라이브러리 채택 기준

1. **사용자 효과:** 어떤 입력·클릭·재작업을 줄이거나 어떤 기능을 추가하는지 한 문장으로 정한다.
2. **정확성:** 동일한 입력과 별도로 계산한 정답 사례로 기존 구현과 비교한다. 좌표·수량·금액의 허용 오차와 근거를 시험 전에 정한다.
3. **호환성:** Node 24, Next.js 15, React 19, 현재 Three.js 계열 및 브라우저/Worker에서 검증한다. 저장소 main의 기능과 실제 배포 패키지를 구분한다.
4. **운영 비용:** 초기 번들, 지연 로딩, 메모리, 계산 시간, 취소·오류·복구를 확인한다. 이미 있는 라이브러리와 역할이 겹치면 필요한 차이를 증명한다.
5. **이용 조건:** 채택할 버전의 LICENSE/NOTICE, 전이 의존성, 모델·데이터·텍스처의 권리를 구분해 기록한다. 허가 미확인 자료를 변형하는 방식으로 도입하지 않는다.
6. **도입 기록:** 정확한 버전, 채택 이유, 비교 결과, 어댑터 위치, fallback, 고지 갱신을 PR에 남긴다. 미채택 후보는 production 의존성에 추가하지 않는다.

라이브러리는 기하 계산·최적화·파일 해석 등을 담당한다. 필지별 규칙, 데이터 출처, 건축 공간 조건, 수량·사업성 연결은 PARCELGRID의 계약으로 관리한다.

### KR-U0 — 기준 사례와 검증 범위

- 기존 쌍문동 회귀 사례를 유지하고 직사각형, 사다리꼴, 오목한 층판, 단차·필로티, 출처 미확인 데이터를 포함한 기하 사례를 준비한다.
- 실제 필지 사례와 합성 기하 사례를 명확히 구분한다. 원문과 비교값을 보관할 수 있는 범위에서 실제 필지를 추가한다.
- 실행 환경과 입력 크기를 고정해 지도 선택, 후보 생성, 저장·복구, 주요 화면 번들을 측정한다. 반복 실행의 지연·메모리와 오류를 남긴다.
- `pnpm verify`와 관련 브라우저 검사를 기록한다. 실제 API/외부 CAD 확인은 자동 테스트 결과와 별도 열로 관리한다.

### KR-U1 — 필지·건물·도로가 보이는 부지 선택

- 선택 필지는 굵은 경계, 주변 필지는 얇은 경계, 기존 건물은 별도 footprint, 도로는 구분 가능한 색으로 표시한다. 범례와 레이어 켜기/끄기를 제공한다.
- 필지와 건물의 식별자를 따로 유지한다. 건물 중심점이나 주소만으로 필지 경계를 새로 만들지 않는다.
- 선택 응답 뒤 주변 맥락을 제한된 범위로 비동기 조회한다. 모든 지도 이동에서 대장·시장·재무 계산을 실행하지 않으며 지연 응답·취소·캐시 키를 선택 revision과 연결한다.
- 레이어별 출처·조회 상태·자료 기준일을 보존한다. 건물 미조회·부분 조회를 빈 부지로 표시하지 않는다.
- 현재 WGS84 경로는 유지한다. 다른 좌표계의 원문을 연결할 때 Proj4js를 시험하고 원본 CRS·축·단위·변환 정의를 저장한다.
- PC·390px 모바일·지도 실패 시 주소 입력, 빠른 재선택·확대·이동 후 클릭·수동 경계 흐름을 검증한다.

완료 기준: 선택 PNU·경계가 현황/3D까지 동일하게 전달되고, 주변 레이어가 선택을 가로채거나 이전 필지 응답으로 덮어쓰지 않는다. API 실패·부분 조회가 범례와 안내에 드러난다. 합성 지도 검사는 실제 좌표를 투영하는 도형으로 검증한다. 현재 테스트의 고정 사각형은 실지도 정합성 증거로 사용하지 않는다. 승인된 실제 API와 지도 타일 확인 전에는 그 항목을 미확인으로 남긴다.

### KR-U2 — 저장·복구와 편집 편의성

- Dexie 기반 IndexedDB 저장 어댑터를 작은 프로젝트로 시험한다. Zustand는 화면 상태를 담당하고 저장 성공은 실제 transaction 완료 후 표시한다.
- 프로젝트 ID·부지 revision·스키마 버전·계획 버전을 함께 저장한다. 기존 sessionStorage/localStorage는 읽기·대조·백업 후 이전하며 실패 시 원본을 보존한다.
- 초안 자동 저장, 저장 중/완료/실패 표시, 가져오기·내보내기·복구를 연결한다. undo/redo 범위는 편집 명령별로 정의한다.
- 이전 형상의 사업성·검토 승인이 최신 계획으로 복구되지 않도록 기존 해시와 revision 계약을 유지한다.

완료 기준: 새로고침·탭 종료 후 재접속·저장 공간 부족·마이그레이션 중단·여러 탭 충돌에서 상태와 복구 경로가 확인된다. Dexie 로컬 저장은 다른 PC 동기화나 외부 백업의 완료를 뜻하지 않는다.

### KR-U3 — 외벽 수량·재료·공사비

작업을 `A. 수량`, `B. 면별 재료`, `C. 단가·보고서`로 나눈다.

- 검증된 층별 외곽선과 높이에서 노출 외벽 수량을 산출한다. 바닥·지붕·내부 공유면을 외벽으로 중복 집계하지 않는다. 중정, 층별 후퇴, 필로티, 개구부와 미확인 접면의 처리 기준을 둔다.
- 자동 계산값을 계획 형상 기반 수량으로 표시한다. 실측값·사용자 입력·기존 면적 환산 추정과 출처를 구분한다. 3D에서 계산했다는 이유만으로 시공 수량을 확정하지 않는다.
- 면별 재료 ID와 단위를 저장하고 벽돌·콘크리트·금속·스타코의 반복 크기가 일정한 재질 표현을 연결한다. 미확인 단가를 텍스처 선택에서 만들어 내지 않는다.
- 재료별 수량과 유효한 기준/선택 단가로 `Σ[면적 × (선택 단가 − 기준 단가)]`를 계산해 기존 공사비와 중복 반영하지 않는다. 출처·시점·부가 항목을 별도로 표시한다.
- 재질 변경은 기준 매스 Geometry Hash를 유지한다. 수량·단가 변경은 사업성·보고서의 계산 버전을 갱신하고 이전 승인과 구분한다. 벽 두께나 실제 개구부 형상 변경은 기하 변경 절차를 따른다.

완료 기준: 직사각형·오목 평면·단차 사례의 별도 계산 수량과 대조하고, 창호 면적이 두 번 공제되지 않는다. 재료 합계와 외벽 총량이 대사되며 단가 없는 부분은 미산정으로 남는다. 화면·Stage 3·보고서가 같은 재료·수량 버전을 사용한다.

### KR-U4 — 내부 평면의 표현과 탐색

**KR-U4A: 공간 데이터와 편집.** 세대→방 계층, 다각형 경계, 공유 벽, 문·창문을 정의한다. Flatten.js는 로컬 미터 평면의 교차·거리·곡선 계산을 시험하고, Turf는 지리 데이터 검증 역할을 유지한다. 스냅·치수·잠금·undo와 이전 직사각형 계획 마이그레이션을 먼저 완성한다. React Flow의 관계 편집이 실제 배치 조건으로 전달되는 경로를 만든다.

**KR-U4B: 조건 기반 생성.** HiGHS를 기존 Comlink Worker에서 시험한다. 초기 범위는 미리 정한 방 크기/방향 또는 격자 모델이다. 최소 면적·복도 연결·겹침 금지·잠금은 필수 조건으로, 선호 인접·동선·면적 편차는 목적함수로 구분한다. 일반 비선형 배치 문제를 그대로 입력하지 않는다.

- 시간 제한, 취소, 계산 실패, 실행 가능한 중간해, 최적성 확인 여부를 구분한다. 현재 템플릿 생성기를 비교 기준과 fallback으로 유지한다.
- 해는 기존 형상·면적 검증을 다시 통과해야 한다. 제한 시간 내 후보 미발견을 건축 불가능이나 전역 최적해 부재로 표시하지 않는다.
- 작은 사례에서 독립적으로 열거한 정답과 비교하고, 불규칙한 층판·조건 충돌·잠긴 공간을 포함한다. 큰 사례는 성능과 미해결 조건을 함께 보고한다.
- HiGHS가 필요한 문제를 표현하지 못하거나 성능 기준을 충족하지 못하면 OR-Tools CP-SAT 실행부를 별도 검토한다. 브라우저 중심 운영에서 서버 솔버로 바꾸는 비용도 비교한다.

완료 기준: 필수 조건 위반 후보가 통과하지 않고, 성공·실패·취소가 UI에 설명된다. 세대/방/공용/잔여 면적이 중복 없이 보존된다. 사업성 반영과 대표안 확정은 같은 공간 버전을 사용한다. 건축가 검토 전에는 상세 설계 적합성이 확인된 것으로 표시하지 않는다.

### KR-U5 — DXF·Shapefile과 기존 내보내기

- shapefile-js + Proj4js: ZIP의 SHP/DBF/PRJ/CPG를 처리하고 좌표계와 한글 속성을 확인한다. 복수 필지는 사용자가 대상을 고르며, 현재 미지원인 내부 구멍·복수 영역은 지원을 구현하거나 명시적으로 거절한다.
- dxf-parser: 지원하는 2D 선·폴리라인·레이어를 참고 도면으로 가져온다. DWG·3D 솔리드를 지원한다고 표시하지 않는다. 도면 선에서 벽·방을 자동 확정하는 기능은 별도 범위다.
- 단위가 없거나 원점을 모르면 사용자가 확인하도록 하고, 원본을 보존한 채 축척·회전·원점 변환을 기록한다. 파일 크기와 요소 수를 제한하고 무거운 해석은 Worker에서 실행한다.
- 기존 DXF/DAE/3DM과 원점·축·미터·층·레이어·Geometry Hash를 대조한다. 수신 앱에서 열리는 것과 같은 수량/형상이라는 것을 따로 확인한다.

완료 기준: 알려진 치수의 샘플, mm/m 혼용, 누락된 PRJ, 한글 인코딩, 여러 레이어, 미지원 요소, 손상 파일에서 결과와 안내가 확인된다. CAD 파일 가져오기가 확인된 필지 경계를 조용히 덮어쓰지 않는다.

### KR-U6 — 환경·상세 3D·보고서

- **주변 차폐:** 기존 SunCalc + BVH에 허용된 주변 건물 footprint·높이를 연결한다. 높이 출처·추정·누락, 좌표·북방향·시간대를 기록한다. 데이터가 없는 영역을 차폐 없음으로 확정하지 않는다.
- **상세 형상:** KR-U4의 벽·개구부 계약 이후 Manifold로 벽·슬래브·개구부를 시험한다. 재료 렌더용 형상과 수량/면적 계산의 기준을 일치시키고 층수·배치·법규용 매스를 임의로 바꾸지 않는다.
- **통행 경로:** 방·문·복도가 정해진 다음 간단한 그래프 경로와 Recast를 비교한다. 문에서 출구까지 도달 가능성과 경로 거리를 표시한다. 법규상 피난 적합성이나 대피 시간 모델은 별도 검증 대상이다.
- **고급 렌더:** three-gpu-pathtracer는 Three.js 버전과 WebGPU 호환 검증 후 별도 출력 모드로 검토한다. 일반 3D와 지원되지 않는 장치의 대체 화면을 유지한다.
- **XLSX:** ExcelJS로 수량·단가·사업성·근거를 전달하는 작업을 검토한다. 계산 원천은 기존 Decimal/ledger이며, 내보낸 값·공식·캐시 결과를 다시 읽어 대사한다. ExcelJS 자체를 재무 계산 엔진으로 사용하지 않는다.

완료 기준: 단순 차폐체의 별도 계산과 그림자 결과를 대조하고 입력 누락을 표시한다. 3D·이미지·XLSX·보고서는 같은 계획·재료·재무 버전을 가리킨다. 외부 CAD/Excel과 실제 지도 확인은 수행 환경·결과를 기록한다.

각 기능 PR에서 다음을 기록한다.

- 변경 전/후 사용자 흐름, 채택/보류한 라이브러리와 버전·이유.
- `pnpm verify`, 해당 기능 브라우저 검사, 필요한 독립 수치 대조 결과.
- 새 production 의존성 도입 시 `pnpm notices:generate`, 의존성 보안 검사와 라이선스 기록.
- 기존 저장 데이터 호환, project/scenario/revision/Geometry Hash, 재료·재무 버전의 일치 여부.
- 같은 입력과 환경의 성능 비교. 무거운 모듈은 필요한 화면/동작에서 로드하고 UI를 막는 계산은 Worker로 분리.
- 실제 확인한 화면/파일과 합성 테스트를 구분한 결과. 실제 API·CAD 환경이 없으면 해당 확인은 미완료로 남기되 독립적으로 검증 가능한 후속 작업은 진행.

새 단계 완료를 근거 없이 이전 데이터·법규·출력의 정확성 보증으로 확대하지 않는다. 치명적인 기존 흐름 회귀나 데이터 유실이 있으면 그 변경의 통합을 중단하고 원인을 먼저 수정한다.
