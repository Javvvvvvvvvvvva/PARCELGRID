# Browser Session Isolation 2026.1

기준일: 2026-10-26, America/Chicago
범위: G08 고객자료 격리의 클라이언트·API 경계. 운영 보안 전체 인수는 아직 미완료다.

## 확인한 위험

기존 `parcelgrid-envelope`, `parcelgrid-review-workflow`는 로그인 주체와 무관한 공통 localStorage 키였다. 부지 입력 sessionStorage와 콘셉트 렌더 메타데이터도 공통 키를 사용했다. 로그아웃은 쿠키만 해제했으며 Query 캐시·메모리·진행 중 자동 저장이 세션 전환에 결속되지 않았다. 따라서 같은 기기의 계정/조직 전환 시 이전 자료 표시와 잘못된 조직으로의 저장 위험이 있었다.

## 현재 계약

1. 고객 화면을 마운트하기 전에 `/api/access/session`에서 조직·사용자를 확인한다. 확인 실패 시 저장소 hydrate와 프로젝트 요청을 시작하지 않는다.
2. 저장소 키는 `parcelgrid:scoped:v1:<context>:<original-key>`다. context는 조직 ID·사용자 ID·역할·정렬한 검토 역할의 JSON을 URI 인코딩한 값이다. 비밀번호·쿠키·인증 토큰이 아니며 암호화 수단도 아니다.
3. Zustand의 자동 hydrate를 끄고 확인된 context의 프로젝트·검토 상태만 복원한다. 부지 초안, 콘셉트 이미지와 참조 이미지도 동일하게 분리한다.
4. 한 JS document는 한 context만 소유할 수 있다. 계정/역할 변경이나 잠금 후에는 새 문서 탐색 없이 재활성화하지 않는다. 늦게 도착한 콜백이 새 고객의 저장소 권한을 얻지 못한다.
5. 로그아웃·로그인 시도 시 다른 탭에 storage event와 BroadcastChannel로 잠금을 알린다. 잠금은 요청 abort, Query 캐시 제거, 고객 메모리 초기화, 화면 제거를 수행한다. 서버 로그아웃 실패는 성공으로 표시하지 않는다.
6. 탭 숨김·페이지 이탈 때 고객 화면을 가린다. 포커스 복귀·pageshow 시 세션을 재검사하며 활성 문서에서도 60초마다 확인한다. 권한 확인 타임아웃은 10초다. 브라우저가 중지된 동안 서버 권한 변경을 즉시 탐지한다고 보장하지 않는다.
7. 모든 현재 고객 API 클라이언트는 `sessionFetch`로 요청한다. 서버는 `x-parcelgrid-session-context`와 현재 인증 주체의 context가 다르면 `409 SESSION_CONTEXT_CHANGED`로 거부한다. Fetch Metadata가 있는 브라우저 요청에 context가 없으면 `409 SESSION_CONTEXT_REQUIRED`다. cookie-only 비브라우저 호출은 기존 인증·역할·조직 검사를 계속 받는다.
8. context 헤더는 인증 또는 CSRF 방어를 대체하지 않는다. 실제 권한·저장 조직·감사 actor는 서버의 서명 세션과 활성 DB 멤버십으로 결정한다.
9. 자동 저장은 해시 계산 전에 실행 잠금을 얻고, 해시 전후·응답 후에 문서/프로젝트 실행 세대를 확인한다. unmount·입력 레코드 교체 시 요청과 예약 재시도를 취소한다. revision 충돌은 세션 변경과 별도로 처리한다.
10. 미저장 Workspace 본문과 기준 revision은 계정별·탭별 sessionStorage 복구 초안으로 보존한다. 화면 이동·새로고침 후 서버를 다시 읽고, 더 최신의 로컬 편집을 오래된 Query 캐시로 덮어쓰지 않는다. 서버 revision이 달라졌으면 초안을 유지하고 충돌을 표시한다. 서버 최신본으로 교체하려면 기존 확인 동작을 거친다.
11. 저장 중 추가 편집이 발생하면 이전 저장 응답으로 `저장됨`을 표시하지 않는다. 최신 편집을 재저장하고 그 응답까지 대기한다. 로그아웃 요청을 시작할 때와 쿠키 삭제가 완료됐을 때 모두 다른 탭에 잠금을 알린다.

## 기존 자료와 제한

- 소유권이 없는 구형 공통 키는 삭제하지도 새 계정으로 자동 이관하지도 않는다. 소유자 확인 및 원본 대조를 거친 명시적 복구가 필요하다. 기존 서버 Workspace는 로그인 조직에 따라 정상 조회한다.
- scoped 자료는 같은 계정의 미저장 초안 복원을 위해 로그아웃 후 로컬에 남는다. 같은 OS/브라우저 프로필을 직접 조작하는 사람, XSS, 악성 확장프로그램으로부터 암호화 격리를 제공하지 않는다. 공용 단말 보존/삭제 정책과 암호화·관리형 단말 요구사항은 운영 인수 항목이다.
- 탭별 Workspace 복구 초안은 sessionStorage 수명에 따른다. 탭 폐기·브라우저 데이터 삭제·저장 공간 부족은 서버 저장의 대체 수단이 아니다. 저장 공간 오류는 표시하고 메모리의 사본은 유지하지만, 창을 닫은 뒤 복원을 보장하지 않는다.
- 이미 서버에 도착해 당시 인증 조직으로 실행된 작업을 로그아웃만으로 롤백하지 않는다. 다른 조직으로 뒤바뀌어 저장되는 것은 context 대조로 거부한다.
- 새 고객 API 호출을 만들 때 raw `fetch`를 추가하면 안 된다. 세션 조회/로그인만 raw fetch를 사용하고 나머지 고객 API는 `sessionFetch`를 사용한다.
- 고객 화면·hook의 raw fetch와 공통 브라우저 저장소 접근은 ESLint에서도 금지한다. 인증 진입점만 예외로 두며 새 예외는 코드 검토가 필요하다.
- 전문 자격·허가·공식 경계 확인 여부, 사업성 숫자·법정 판정은 이 변경으로 승격되지 않는다.

- 해당 브라우저 시험은 인증된 개발 서버와 임시 local-versioned backend다. 운영 모드에서 DB 미설정 시 로그인을 차단하는 보호를 확인했으며 우회 코드를 추가하지 않았다. 기존 Multipass PostgreSQL VM은 이번 실행에서 SSH host down/timeout으로 연결되지 않아 최신 실제 DB 재검증은 남아 있다.
- 전체 자동 검증은 818개 통과, PostgreSQL 통합 1개 건너뜀. 빌드·lint·typecheck 통과. 이 결과는 G08 전체 통과나 출시 인수가 아니다.
- 독립 코드 검토에서 추가 발견한 미저장 초안 덮어쓰기, 이전 응답의 조기 저장 완료 표시, 로그아웃 중 새로고침 경쟁 조건을 보완했다. 브라우저 재현 시험에 화면 이동/새로고침 복구, 저장 중 추가 편집, 원격 revision 충돌과 명시적 교체, 지연 DELETE 도중 탭 재로딩을 추가하여 통과했다.
- 같은 날짜에 평면/사업성 연결과 상세 실/피난 브라우저 회귀도 계정별 저장 키로 다시 통과했다. 증빙은 위 디렉터리의 `layout-finance/`, `room-egress/`에 있고, 합성 도형이며 실제 필지 검산이 아니다.
