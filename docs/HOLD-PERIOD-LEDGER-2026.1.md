# Hold Period Ledger 2026.1

> 역사 버전이다. 현행 계약은 `HOLD-PERIOD-LEDGER-2026.2.md`를 따른다.

## 목적과 적용 범위

`hold-period-ledger-2026.1`은 임대 안정화 후 즉시 매각하는 기존 개발 수익률과, 장기대출로 PF를 상환한 뒤 자산을 보유하는 대안을 분리해 비교한다. 개발 원장의 기본 손익·IRR·NPV를 덮어쓰지 않으며 현재 공통 Pareto 순위에도 포함하지 않는다.

첫 버전은 매각 수익 풀이 없는 전부 임대형만 계산한다. 혼합 매각·임대형은 `not-applicable`로 남긴다.

## 연결 계약

입력은 다음 세 계약에서 온다.

1. `project-ledger-2026.6`: 개발 자기자본 월별 현금흐름과 임대 안정화 직전 PF 원금
2. `revenue-valuation-2026.2`: 임대면적, 잠재 임대료, 공실, 운영비, NOI와 안정화 자산가치
3. `takeout-underwriting-2026.1`: 장기대출 실행액, 수수료 차감 순유입액, 금리, 상환기간과 재융자 부족액

보유 원장은 개발 원장의 안정화 매각 회수액을 아래처럼 교체한다.

```text
재융자월 자기자본 현금흐름
= 개발 원장 종료월 자기자본 현금흐름
- 안정화 임대 자산가치
+ 장기대출 수수료 차감 순유입액
- 최초 임차인 공사비
- 최초 임대 중개수수료
```

전부 임대형의 개발 종료월은 임대 안정화 월과 같아야 한다. 사용되지 않는 분양·매각 기간이 이 시점을 늦추지 않도록 개발 원장 2026.6에서 분리했다.

## 보유 운영 계산

보유기간은 정수 년이며 월별로 계산한다.

```text
월 잠재 임대료 = 안정화 연 잠재 임대료 / 12 x (1 + 연 임대료 성장률)^((월-1)/12)
월 예정 임대료 = 월 잠재 임대료 x (1 - 공실률)
월 유효총수입 = 월 예정 임대료 - 초기 무상임대
월 운영비 = 안정화 연 운영비 / 12 x (1 + 연 운영비 성장률)^((월-1)/12)
월 NOI = 월 유효총수입 - 월 운영비
월 교체 준비금 = 임대면적 x 연 면적당 준비금 / 10,000 / 12 x 운영비 성장계수
```

최초 임차인 공사비는 `임대면적 x 원/㎡ / 10,000`으로, 최초 중개수수료는 `안정화 연 예정 임대료 x 수수료율`로 계산해 재융자월에 반영한다. 대수선은 지정 연차 말에 일회성 자기자본 유출로 반영한다.

## 보증금 경계

보증금은 `안정화 월 예정 임대료 x 입력 개월 수`로 계산한다. 반환 의무가 있는 제한현금이므로 원장 행에는 유입, 잔액과 종료 환급을 기록하지만 다음에는 사용하지 않는다.

- PF 상환
- 장기대출 원리금 상환
- 운영비 지급
- 투자자 배당과 IRR·NPV·Equity Multiple

보증금 운용수익도 계산하지 않는다.

## 장기대출과 Exit

장기대출은 입력 금리와 상환기간의 월 원리금 균등상환액을 적용한다. 매월 이자와 원금을 분리하고 최종 매각월에 남은 원금을 전액 상환한다.

```text
종료 연 NOI
= 종료 시점 성장 임대료 x (1 - 공실률)
- 종료 시점 성장 운영비

최종 매각가 = max(종료 연 NOI, 0) / Exit cap rate
매각 부대비 = 최종 매각가 x 매각 부대비율

월 지분현금흐름
= NOI
- 교체 준비금
- 대수선
- 장기대출 원리금
+ 최종 매각가(종료월)
- 매각 부대비(종료월)
- 잔존 장기대출 원금(종료월)
```

연 DSCR은 해당 연차 NOI를 같은 연차 장기대출 원리금으로 나눈 값이다. 보유기간 최저 연 DSCR을 별도로 반환한다.

## 결과와 상태

결과는 개발과 보유를 연결한 세전 손익, NPV, IRR, Equity Multiple, 누적 회수월, 연차별 EGI·운영비·NOI·원리금·DSCR, 최종 매각가와 대출상환액을 보존한다.

- `not-applicable`: 임대가치·NOI가 없거나 매각 풀을 섞은 안
- `not-configured`: 보유기간 0년
- `terms-missing`: Exit cap 또는 장기대출 필수 조건 미입력
- `terms-invalid`: 허용 범위를 벗어난 입력
- `modeled-unverified`: 계산은 가능하지만 장기대출 확약 미확인
- `refinance-shortfall`: 수수료 차감 순대출액이 PF 원금보다 부족
- `commitment-feasible`: 입력 확약액 기준 PF 상환 가능

IRR은 0이 아닌 현금흐름의 부호가 한 번만 바뀌고 수치해가 있을 때만 표시한다. 부호가 여러 번 바뀌면 `ambiguous`, 해가 없으면 `not-calculated`다.

## 소스 데이터 게이트

보유기간이 0보다 큰 전부 임대형은 다음 12개 입력의 원문·발급기관·기준일·확인자를 요구한다. 현재 계산하지 않는 혼합 매각·임대형에는 이 자료 때문에 소스 게이트가 막히지 않는다.

1. 보유기간
2. 연 임대료 성장률
3. 연 운영비 성장률
4. 초기 무상임대 기간
5. 임차인 공사비
6. 임대 중개수수료율
7. 보증금 개월 수
8. 연간 면적당 교체 준비금
9. 대수선 발생 연차
10. 대수선 비용
11. 보유 종료 Exit cap rate
12. 매각 부대비율

0 입력이 실무상 가능한 항목도 승인 정책, 계약, 감정평가 또는 견적 근거가 있어야 소스 게이트를 통과한다. 보유기간과 Exit cap rate는 0을 검증값으로 인정하지 않는다.

## 미산정 경계

- 재산세, 부가세, 법인세와 세금 납부 시점
- 임차인 교체·갱신, 후속 무상임대·TI·중개수수료와 재공실
- 임대료 연체, 대손과 임대차별 만기 구조
- 변동금리, 거치·이자-only 구간, 만기연장과 상환준비금
- 보증금 운용수익과 제한계정 이자
- 혼합 매각·임대형의 보유 수익 배분

따라서 결과는 세전 예비 비교값이며 금융기관 승인액, 감정평가액 또는 세후 확정수익이 아니다.

## 회귀 기준

- 보유 입력은 기존 안정화 매각 손익·IRR·NPV와 개발기간을 바꾸지 않는다.
- 개발 종료월의 안정화 매각가를 제거하고 장기대출 순유입액을 한 번만 넣는다.
- 상환 원금 합계와 최종 대출상환액의 합이 장기대출 실행액과 일치하고 종료잔액은 0이다.
- 보증금 잔액은 종료 시 0이지만 보증금 유입·환급은 지분수익률을 바꾸지 않는다.
- 무상임대, TI, 중개수수료, 준비금과 대수선은 각각 보유 손익·NPV를 낮춘다.
- 같은 NOI에서 낮은 Exit cap rate는 최종 매각가를 높인다.
- 입력 객체와 개발 현금흐름 배열을 변경하지 않는다.
