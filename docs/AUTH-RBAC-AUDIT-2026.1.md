# PARCELGRID 인증·권한·감사 계약 2026.1

기준일: 2026-09-09

## 신뢰 경계

PARCELGRID는 사용자 ID, 조직 ID, 조직 역할과 분야별 전문가 역할을 가진 서명
세션을 사용한다. 브라우저가 보낸 actor ID, 역할, 소속은 신뢰하지 않는다.
`DATABASE_URL`이 있으면 매 API 요청에서 활성 사용자와 조직 멤버십을 다시 읽고
DB의 최신 역할을 권한 기준으로 사용한다. 비활성화·조직 불일치는 즉시 거부한다.

내장 `SITE_ACCESS_ACCOUNTS_JSON` 계정은 소규모 역할 분리형 배포 게이트다. 법적
전자서명, 기업용 IdP, SSO 또는 MFA를 대신하지 않는다.

## 조직 역할

| 역할 | 주요 권한 |
|---|---|
| `owner` | 전체 프로젝트·승인·감사·멤버 관리 |
| `admin` | 프로젝트·분석·근거·승인·감사 관리 |
| `analyst` | 분석, 계획·가정 수정, 근거 업로드, 검토 요청 |
| `reviewer` | 읽기, 분야 자격 범위의 검토·승인, 감사 열람 |
| `viewer` | 프로젝트 읽기 전용 |

전문가 승인에는 조직 역할의 `review.perform` 권한과 해당 분야 전문가 역할이
모두 필요하다. 요청자는 같은 Snapshot을 직접 검토할 수 없고, 검토를 시작한
담당자만 승인 또는 수정 요청을 기록할 수 있다.

## 감사 원장

가정 변경, 원문 업로드, AI 렌더, 전문가 상태 전이는 조직별 단일 순번과 이전
이벤트 해시를 가진 SHA-256 체인에 기록한다. 이벤트에는 서버가 확인한 사용자,
역할, 조직, 서버 시각, 요청 ID, payload 해시가 포함된다.

- PostgreSQL: 조직 advisory lock과 `(org_id, ordinal)` 유일성으로 순서를 정하고
  DB 트리거가 `audit_log`와 `assumption_overrides`의 수정·삭제·truncate를 막는다.
- 로컬 대체 경로: 권한 `0600` JSONL append와 프로세스 내부 직렬화를 사용한다.
  여러 서버 프로세스 간 동시성이나 WORM 보관을 보장하지 않는다.
- 읽기 시 전체 조직 체인을 재검증한다. 누락·변조가 있으면 검토와 보고서 확정을
  계속하지 않고 `503`으로 중단한다.

## 운영 조건

공유 운영은 사용자별 계정, 별도 32자 이상 세션 비밀값, PostgreSQL과 생성된
불변 트리거 migration 적용이 필요하다. 다중 인스턴스에서는 외부 IdP와 공유
rate limiter, 관리형 객체 저장소, 키 회전·세션 폐기·백업 정책을 추가한다.

현재 프로젝트 편집본은 브라우저 저장을 사용하지만 전문가 검토에 들어가는 Stage 3
계산·Geometry 식별자·원문 메타데이터·가격 검증·세무 계약 묶음은 서버가 정규화해
SHA-256으로 봉인한다. 승인 이벤트는 이 봉인 키와 봉인 이벤트 감사 해시를 함께
가져야 한다. 전체 프로젝트의 여러 PC 동기화는 별도 서버 프로젝트 저장 계약이
필요하다.
