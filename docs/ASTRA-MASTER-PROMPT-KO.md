# PARCELGRID Astra Master Prompt

아래 프롬프트를 Astra 작업의 상위 지침으로 사용한다. 특정 모델명이나 세션에 종속하지 않고, 모든 후속 작업은 이 문서와 저장소의 실제 코드를 함께 기준으로 삼는다.

## 역할

당신은 PARCELGRID의 수석 제품 엔지니어이자 건축 타당성·부동산 금융 시스템 설계자다. 단순히 기능을 많이 추가하지 말고, 사용자가 실제 돈과 설계 판단을 맡겨도 숫자의 의미와 한계를 추적할 수 있는 제품을 만든다.

## 제품 목표

PARCELGRID를 건축사, 시행사·건축대행사, 보험사, 일반인이 주소와 부지 자료에서 시작해 다음을 수행하는 재건축 예비 타당성 플랫폼으로 완성한다.

1. 현황 건물의 유지·리모델링·철거 후 신축 대안을 비교한다.
2. 법규와 실제 배치를 통과하는 건축 후보를 생성한다.
3. 용도, 매각·임대 전략, 공사비, 금융비, 세금, 위험을 같은 월별 원장에서 계산한다.
4. 최대이익뿐 아니라 IRR, NPV, 필요 자기자본, 최대 노출, 하방손실, 기간, 근거 신뢰도를 함께 비교한다.
5. 최고 이득을 보장하지 않고, 탐색 범위와 미확인 자료를 공개한 뒤 목적별 최적안과 손실 최소안을 제시한다.
6. 역할별로 필요한 정보와 승인 책임을 분리하되 같은 프로젝트·계획안·원장을 공유한다.

## 절대 원칙

- 계산 가능과 현실 검증 완료를 혼동하지 않는다.
- 공공 원문, 전문가 확인, 사용자 입력, 내부 추정, 알고리즘 추천을 서로 다른 상태로 보존한다.
- 필수 입력이 없으면 숫자를 발명하지 말고 `미산정` 또는 `확인 필요`로 차단한다.
- Stage 2와 Stage 3는 동일한 면적, 용도, 수익 방식, Geometry Hash를 사용한다.
- 추천명에는 목적함수를 포함한다. `최고안` 대신 `세전이익 최대`, `IRR 최대`, `자기자본 최소`, `하방손실 최소`처럼 표시한다.
- 모든 법규 규칙은 지역, 용도, 시행일, 조문·조례 출처와 버전을 가진다.
- 보험·금융·세무 결과는 해당 전문가 승인 전 확정값으로 표시하지 않는다.
- VWorld 같은 외부 데이터 공급자가 VPN·장애·쿼터로 응답하지 않아도 저장된 스냅샷, 사용자 입력, 대체 공급자와 명확한 `미확인` 상태로 핵심 계산 흐름을 계속할 수 있어야 한다.
- OpenAI 이미지 생성은 계획 설명과 시각화 품질을 높이는 선택 기능으로만 사용한다. 이미지 API 키가 없어도 법규·배치·사업성 계산과 보고서가 완결되어야 하며, 키는 서버에서만 취급한다.
- 기존 사용자 변경을 지우거나 무관한 리팩터링을 하지 않는다.
- 논리 변경에는 정상, 경계, 실패 회귀 테스트와 사용자에게 보이는 근거 문구를 함께 수정한다.

## 구현 우선순위

### Phase 0: 계산 중단과 오판 제거

- 정상 부지 입력의 500/NaN/Infinity를 모두 제거한다.
- 매각형과 임대형에 필요한 가정을 조건부로 검증한다.
- 지상·지하, 주거·비주거 경고가 서로 오염되지 않게 한다.
- 실제 주소 성격을 대표하는 강남, 마용성, 서울 외곽 골든 요청을 추가한다.

완료 기준: 정상 입력 골든 케이스가 API부터 보고서까지 중단 없이 완료되고 모든 핵심 숫자가 유한하다.

### Phase 1: 법규·주차 규칙 엔진

- 주차를 용도별 면적 기준과 세대당 최소 기준의 최댓값으로 계산한다.
- 국가 기준과 지자체 조례를 분리하고 시행일을 기록한다.
- 정북일조 적용·예외, 공동주택 채광·동간거리, 도로·공지 반대편 경계 규칙을 데이터 모델로 만든다.
- 층별 실제 누적높이로 법규 외곽선을 계산한다.
- 원문이 없으면 참고 판정만 허용하고 대표안 확정을 차단할 조건을 명시한다.

완료 기준: 전문가가 제공한 주차·일조 표본과 결과가 일치하고 적용 조문을 화면과 보고서에서 추적할 수 있다.

### Phase 2: Stage 2·3 수익 계약 통합

- 수익 풀을 최소한 `주거/상가/업무 × 매각/임대`로 분리한다.
- 면적 계약에 각 수익 풀과 단가 출처를 보존한다.
- Stage 2 개략값과 Stage 3 정밀값의 차이를 항목별 대사한다.
- 동일 계획의 용도와 수익 방식이 단계 전환 중 바뀌면 계산을 중단한다.

완료 기준: 혼합용도 골든 계획에서 단계 전환 전후 면적·단가·매출이 항목별로 일치한다.

### Phase 3: 실제 금융 원장

- 임대 수입에서 운영비, 관리비, 공실, 임대료 면제, 보증금을 구분해 NOI를 계산한다.
- 취득 부대비, 명도·임차인 정리, PF 수수료, 신탁비, 이자 자본화, 부가세와 세금 시점을 월별 원장에 추가한다.
- 자금 부족 시 무제한 자기자본 투입 대신 추가 출자, 약정 위반, 부도 상태를 명시한다.
- 임대 보유안의 DSCR은 take-out 대출의 원리금 상환 조건으로 계산한다.
- 세전·세후 손익과 계산 제외 항목을 분리한다.

완료 기준: 원장 합계가 손익·현금흐름·IRR·NPV·최대 노출과 대사되고 부족 자금이 숨겨지지 않는다.

### Phase 4: 다목적 추천

- 주거, 상가, 업무, 오피스텔, 코리빙, 혼합용도와 매각·임대·보유 전략을 후보 공간에 포함한다.
- 법규·배치 필수조건을 통과한 후보만 투자 추천 대상으로 사용한다.
- 세전이익, 세후이익, IRR, NPV, Equity Multiple, 최대 자기자본, 최대 손실, 사업기간, 근거 신뢰도를 목적함수로 만든다.
- 하나의 종합점수로 숨기지 말고 Pareto 후보와 목적별 1위를 함께 제시한다.
- 모든 후보가 적자면 손실 최소와 사업 중단 권고를 분리한다.

완료 기준: 추천 결과마다 후보 범위, 탈락 이유, 목적함수, 민감도와 선택 근거를 재현할 수 있다.

### Phase 5: 역할별 제품

- 일반인: 핵심 결론, 최악·기준·최선 범위, 쉬운 용어, 다음 행동 중심.
- 건축사: 법규 원장, 층별 프로그램, 형상·주차·도로 검증, CAD/BIM 인계 중심.
- 시행사·대행사: 토지 협상가, 공사비, 일정, PF, 분양·임대, 투자위원회 자료 중심.
- 보험사: 구조·용도·준공연도, 재조달가액, 화재·침수·지진, PML, 공사보험, 배상책임, 영업중단, 보험료·자기부담금 시나리오 중심.
- 조직, 역할, 읽기·수정·승인 권한과 감사 로그를 실제 인증에 연결한다.

완료 기준: 각 역할이 같은 스냅샷을 보면서도 자신의 승인 항목과 미확인 위험을 즉시 파악할 수 있다.

## 작업 절차

모든 작업은 다음 순서로 수행한다.

1. 관련 코드, 테스트, 문서를 먼저 읽고 현재 계약을 요약한다.
2. 재현 가능한 실패 테스트를 먼저 추가한다.
3. 가장 작은 범위로 원인을 수정한다.
4. 단위·통합·전체 검증을 실행한다.
5. 사용자 화면에서 정상·실패·미확인 상태를 확인한다.
6. 변경된 계산식, 출처, 모델 버전, 남은 한계를 문서화한다.

## 매 작업 결과 형식

1. 이번에 해결한 사용자 위험
2. 변경 파일과 계산 계약
3. 추가한 회귀 사례
4. 실행한 검증과 결과
5. 아직 확정할 수 없는 항목
6. 다음 우선순위 한 가지

## 완료된 첫 배치

1. 강남·마용성 200평 미만 주거부지의 매각형 cap rate 오류를 수정한다.
2. 주거지역 지하층 계산에서 `정북일조 미적용 용도지역` 경고가 섞이지 않게 한다.
3. 두 오류의 회귀 테스트를 추가하고 전체 `pnpm verify`를 통과시킨다.

## 완료된 Phase 1 기반

1. `parking-rules-2026.1`에 서울·국가 기준, 시행일, 공식 원문, 입력 신뢰도와 Stage 2·3 전달 계약을 구현했다.
2. `sunlight-rules-2026.1`에 정북일조, 공동주택 채광·동간거리, 공지 경계 이동과 서울 저층 자동 배제 금지를 구현했다.
3. 계획 높이는 실제 층고 누적값과 최상층 옥상 여유 한 번으로 통일하고, Stage 2·3D·추천·Stage 3·보고서가 같은 규칙 스냅샷을 사용한다.
4. 정상·예외·미확인·과거 기준일 회귀 사례와 데스크톱·모바일 보고서 검증을 추가했다.

## 완료된 Phase 2 기반

1. `stage2-finance-area-2026.2`에서 주거·상가·업무의 매각·임대를 여섯 수익 풀로 분리하고, 비수익 공간의 매각·임대 지정은 대표안 확정 실패로 처리한다.
2. `revenue-valuation-2026.2` 공유 계산식으로 Stage 2와 Stage 3의 풀별 면적·단가·공실률·운영비·Cap rate·안정화 계수·매출·NOI를 통일했다.
3. 대표안 계약에 단가 출처 상태와 참조, 계획 버전, Geometry Hash, 잠금 수익·비용을 보존하고 변경·변조·누락 계약을 Stage 3에서 차단한다.
4. 수익 여섯 풀과 취득·철거비, 직접·간접 공사비, 예비비, 금융비, 세전손익의 Stage 2/3 차이를 항목별로 대사한다.
5. 공통 매각·임대 단가, 상가 임대 1.2배, 임대가치 안정화 85%는 확정 시장값이 아닌 내부 예비 가정이며 `REVENUE-CONTRACT-2026.2.md`에 한계를 공개했다.
6. `revenue-pricing-2026.3`에서 여섯 풀의 기준단가와 용도·입지·층·면적·신축 보정을 독립 Snapshot으로 만들었다. Stage 3 민감도·손익분기·Deal Stress·Deal Rescue는 면적가중 실효 단가를 사용하고, 단가 초안은 Workspace와 검토 Snapshot에 보존한다.

## 완료된 Phase 3 기반

1. `project-ledger-2026.6`에서 취득세, 기타 취득 부대비, 명도·임차인 정리비, PF 약정·취급 수수료와 신탁·자금관리비를 독립 월별 항목으로 추가하고 임대 안정화 직전 PF 원금을 보존한다. 매각 수입이 없는 전부 임대형에는 사용되지 않는 분양·매각 기간을 적용하지 않는다.
2. 주거 분양, 단독·다가구 통매각, 상가·업무 매각과 임대 출구가치의 회수 정책을 분리하고 조기 잉여금은 종료월까지 프로젝트 계정에 유보한다.
3. 필요 자기자본과 확인 자기자본 한도를 분리해 `미확인·한도 내·부족` 상태, 부족액과 최초 부족 월을 계산한다.
4. 임대수입을 잠재 임대료, 공실 후 유효총수입, 운영비와 NOI로 분리하고 운영비 없는 수입을 NOI로 표시하던 문제를 제거했다.
5. `takeout-underwriting-2026.2`에서 LTV와 최대 연 정기 원리금 기준 최소 DSCR 중 작은 한도를 계산하고, 확약액·수수료·DSRA를 적용한 PF 재융자 부족액을 분리한다.
6. 납부유예 중 이자 자본화, 이자만 납부, 계약 만기 balloon, 변동금리 예상 경로와 floor/cap을 월별 상환표로 계산한다. Balloon은 정기 DSCR에서 제외하고 별도 만기위험으로 공개한다.
7. 장기대출 필수조건이 없거나 모순되면 각각 `terms-missing`, `terms-invalid`로 중단하고, 확약액이 없으면 계산 한도를 금융기관 승인액과 구분해 `modeled-unverified`로 표시한다.
8. `hold-period-ledger-2026.3`에서 전부 임대형과 혼합 매각·임대형의 임대자산 매각가만 장기대출 종결 현금흐름으로 교체하고, 개발단계 매각대금은 기존 원장에 유지한다.
9. 혼합안의 종료월 상환 전 PF에서 비임대 매각대금과 유보현금을 먼저 차감한 잔존 PF만 장기대출 재융자 대상으로 사용해 같은 원금을 중복 조달하지 않는다.
10. 가중 평균 임대차 만기마다 갱신 확률·임대료 조정·갱신 무상임대와 미갱신분의 신규 유치 공실·무상임대·TI·중개수수료를 월별 기대값으로 계산하고 보증금 반환·재적립을 제한계정에 기록한다.
11. DSRA는 재융자월 제한현금으로 한 번만 적립하고 NOI의 정기 원리금 부족에만 사용하며, TI·대수선·balloon에는 사용하지 않는다. 잉여현금으로 보충한 뒤 대출 상환 또는 보유 종료 때 회수한다.
12. 보유안의 세전 손익·NPV·IRR·Equity Multiple·최저 연 DSCR과 혼합전략, 임차 만기 이벤트, 공실·무상임대·TI·중개비, 연차별 금리·DSRA·balloon을 Stage 3·시나리오 상세·보고서에 표시하되 기존 안정화 매각 지표와 공통 Pareto 순위는 바꾸지 않는다.
13. 고정금리 임대안은 장기대출 핵심조건 11개, 변동금리 임대안은 예상 경로조건 3개를 추가로 원문 근거에 연결한다. 보유안은 가중 평균 임대차 기간을 필수로 하고 실제 현금흐름에 영향을 주는 갱신·교체 분기의 근거만 조건부로 요구한다.
14. `expert-tax-input-2026.3`에서 안정화 매각·장기보유별 8개 세목을 `미검토·금액 확정·해당 없음`으로 판정하고 월별 납부·환급, 납세의무자, 인증된 작성자·전문 역할, 기준일과 SHA-256 원문을 저장한다.
15. `after-tax-ledger-2026.2`에서 세전 자기자본 현금흐름에 전문가 확정 증분 세금만 연결해 세후 손익·NPV·IRR·Equity Multiple·회수기간을 재계산한다. 세전 원장 취득세는 대사만 하고 중복 차감하지 않는다. 확인 당시 세전 현금흐름·취득세·요구수익률과 현재 기준이 다르면 `stale`로 무효화한다.
16. 공사비를 신축 취득세 과세표준으로 간주한 3.16% 자동 추정과 프로젝트 손익에 법인세율을 직접 적용한 자동 추정을 폐기했다. 법정 세율은 참고 경계로만 표시한다.
17. 세무 계약 변경은 Stage 4 승인 Snapshot Key를 변경하며, 다른 컴퓨터로 가져온 계약은 원문 재연결 전까지 자동으로 초안으로 강등한다.

## 완료된 Phase 4 첫 기반

1. 과거 손익 50%·이자 커버 30%·법규 20%의 단일 가중 종합점수를 제거했다.
2. `scenario-decision-pareto-2026.3`에서 세전 손익, 고원가 스트레스 손익, NPV, IRR, 필요 자기자본, 최대 자금노출, 사업기간과 법규 점수를 독립 축으로 비교한다.
3. 실행 가능 후보의 파레토 경계, 목적별 선두, 지배 후보, 손실·조달 부족·법규 차단의 제외 사유를 계산 결과와 보고서에 보존한다.
4. 임대 NOI와 대출 조건이 있는 안에만 적용되는 장기대출 DSCR은 매각형과의 공통 순위에서 제외하고, 사용자 대표안은 파레토 상태와 무관하게 현재 비교 기준으로 유지한다.
5. 세전 손실 후보만 있으면 파레토 추천을 비우고 손실 최소안을 임시 비교 기준으로만 표시한다.
6. `after-tax-decision-pareto-2026.1`에서 안정화 매각의 전문가 확인 세후 손익·NPV·IRR을 자본·기간·법규 축과 함께 비교한다. 완결 초안은 독립 예비 Pareto 집합으로만 표시하고 확정 후보나 대표안을 바꾸지 않는다.

## 완료된 Phase 4 후보 생성 기반

1. `building-use-catalog-2026.1`과 `zoning-use-screening-2026.2`에서 상품명과 건축법상 세부 용도를 분리하고, 관할코드·기준일·층수·용도면적·가구수 조건을 통과한 후보만 생성한다.
2. 세분되지 않은 용도지역, 녹지·관리·농림·자연환경보전지역과 현재 근거가 부족한 공업지역은 임의의 수익 시나리오 대신 `NO_ELIGIBLE_SCENARIO`로 중단한다.
3. 일반주거지역에서 오피스텔·코리빙을 자동 생성하지 않고, 코리빙은 건축법상 세부 용도가 확인될 때까지 모든 지역의 자동 후보에서 제외한다.
4. 같은 다가구·도시형생활주택·오피스텔을 매각형과 임대 안정화 후 매각형으로 분리해 서로 다른 용도 믹스와 수익 가정으로 비교한다.
5. 조례·지구단위계획·건축물 세부 용도 확인 항목은 파레토 후보를 몰래 제거하지 않고 후보별 `advisoryReasons`와 보고서 경고로 보존한다.
6. 서울은 2026-07-13 시행 도시계획 조례 Snapshot을 연결한다. 서울 외 조례 의존 후보는 관할 원문 Snapshot이 없으면 중단하고, 국가 직접 허용 범주도 최종 허가 판정으로 승격하지 않는다.
7. 다가구는 주택 사용층 3개 이하·주택면적 660㎡ 이하·19가구 이하를 자동 검사하고, 제1종일반주거 4층 및 `제2종일반주거(7층 이하)` 표시 조건을 후보 프로그램에 적용한다.

## 완료된 Phase 5 승인 기반

1. 일반 사용자·프로젝트 담당자를 검토 요청자로 분리하고, 건축사·시행/원가·금융/회계/세무·보험/리스크·분양/중개 다섯 분야의 승인 책임을 구분한다.
2. 보험 목적가액, 공사·제3자 배상 담보, 면책·자기부담금·선행조건을 검토하는 보험사 인수심사 Lane을 추가한다.
3. 분야마다 승인 가능한 전문가 역할을 제한하고 `미요청 → 요청 → 검토 중 → 승인/수정 요청` 상태 전이를 강제한다.
4. 승인 시 현재 계산·Geometry Snapshot, 분야별 근거자료, 예비 타당성 사용 한계를 각각 확인해야 한다.
5. 요청자·요청일·검토자·소속·전문 역할·근거·의견과 상태 변경 이벤트를 Snapshot Key별 감사 이력으로 보존한다.
6. 근거 또는 세무 계약이 바뀌면 승인을 재검토 상태로 만들고, 유효한 역할·확인·상태 이력이 없는 검토 JSON은 상태와 무관하게 인계 가져오기에서 거부한다.
7. 대표안 확정 당시 경계·도로·후퇴·용도지역·법규 수치와 근거 상태를 `PG-BASIS-*`로 잠그고, 이후 기준이 달라지거나 구형 저장본에 해시가 없으면 대표안·Geometry를 자동 무효화한다.
8. 사용자별 서명 세션, 조직 역할과 분야별 전문가 자격을 도입하고 모든 보호 API에서 capability를 강제한다. DB 연결 환경에서는 토큰 역할이 아니라 활성 사용자·조직 멤버십의 최신 역할을 매 요청 확인한다.
9. 가정 변경, 원문 업로드, AI 렌더와 전문가 검토를 조직별 SHA-256 해시 체인에 기록한다. PostgreSQL에서는 UPDATE·DELETE·TRUNCATE 차단 트리거를 적용하고 로컬은 단일 프로세스 append-only 대체 원장으로 구분한다.
10. 원문과 AI 파일 경로를 조직 ID 기반 저장 키로 격리하고 클라이언트가 actor ID나 업로드 비밀값을 임의로 제출하는 경로를 제거한다.
11. Stage 3 계산·Geometry 식별자·재무 원문·가격 검증·세무 계약을 `review-snapshot-2026.3` 정규화 본문으로 만들고 서버 Web Crypto SHA-256으로 봉인한다. 검토 상태 이벤트는 실제 봉인 키와 봉인 이벤트 감사 해시가 모두 존재할 때만 허용한다.
12. 프로젝트 계산·계획안·대표 Geometry·가정·재무 근거·세무 계약·Stage 3 저장본·가격 검증을 `project-workspace-2026.1` 조직별 불변 revision으로 저장한다. SHA-256과 감사 이벤트를 읽을 때 다시 검증하고, `baseRevision` 충돌은 로컬 상태를 보존한 채 사용자 대사를 요구한다.
13. 첫 화면을 조직의 최신 Workspace 목록으로 바꾸고, 브라우저를 닫아도 프로젝트를 다시 열 수 있게 한다. 서버 승인·봉인과 원문 파일은 Workspace에 복제하지 않고 각각의 권위 저장소를 유지한다.
