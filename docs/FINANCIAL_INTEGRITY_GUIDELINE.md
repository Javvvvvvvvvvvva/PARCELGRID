# PARCELGRID 데이터·계산 신뢰성 가이드라인

상태: **필수 제품 규칙**  
버전: `integrity-2026.1`  
적용 범위: Stage 1 현황 분석부터 Stage 5 보고서까지의 가격·면적·원가·금융·세금·출처·전문가 검토

## 1. 목적

PARCELGRID의 목표는 자동으로 확정 판단을 만드는 것이 아니라, 건축가·시행사·금융·회계·세무 전문가가 같은 대상과 같은 원장을 보며 빠르게 검토할 수 있는 재현 가능한 사전검토 자료를 만드는 것이다.

다음 세 조건을 모두 만족하지 않는 숫자는 확정값으로 표시하지 않는다.

1. 계산 대상과 단위가 명확하다.
2. 원문 출처 또는 공개된 내부 가정이 있다.
3. 동일 입력으로 결과를 재현하고 중간 계산을 대사할 수 있다.

`source-backed`, `engine-calculated`, `expert-approved`는 서로 다른 상태다. 어느 하나도 다른 상태를 자동으로 의미하지 않는다.

## 2. 절대 원칙

### 2.1 하나의 개념에는 하나의 의미만 사용한다

- `acquiredPrice`는 **부동산 총 취득대금**을 뜻한다.
- 기존 건축물이 있는 경우 총 취득대금은 토지와 기존 건물의 권리를 함께 취득하기 위해 실제 지급하거나 지급할 계약상 대가다.
- 총 취득대금과 토지 배분가액을 같은 필드나 같은 라벨로 사용하지 않는다.
- 총 취득대금에 이미 포함된 기존 건물 가액을 사업비에 다시 더하지 않는다.
- 철거비·명도비·중개/법무비·세금은 총 취득대금과 별도 항목이다.

### 2.2 계산 면적을 다시 추정하지 않는다

Stage 2가 확정한 면적은 Stage 3의 원본이다. Stage 3는 FAR와 일반 전용률로 면적을 재생성하지 않는다.

필수 전달 면적:

- 실제 지상 공사면적
- 실제 지하 공사면적
- 용적률 산입면적
- 매각 가능 면적
- 임대 가능 면적
- 주차·필로티 면적
- 코어·공용면적
- 실제 계획 주차대수

### 2.3 원본과 파생값을 구분한다

- 국토교통부 실거래 원문은 `official-source`다.
- 실거래 중앙값, 점수, 보정률을 적용한 값은 `derived-estimate`다.
- 검토자가 사례를 선택하고 조정한 값은 `reviewed-estimate`다.
- 감정평가서·계약서·견적서·금융기관 약정에 의해 확정된 값만 해당 문서 종류로 표시한다.
- 파생값을 `official-api` 또는 확정 시세로 저장하지 않는다.

### 2.4 화면 밖의 비용도 원장에 존재해야 한다

IRR·NPV·최대 취득대금에 영향을 주는 비용은 참고 카드가 아니라 월별 원장에 들어가야 한다.

최소 원장 항목:

- 부동산 총 취득대금
- 취득 부대비용
- 기존 건물 명도·임차인 정리비
- 철거비
- 지상 직접 공사비
- 지하·주차 직접 공사비
- 설계·감리·인허가·간접비
- 예비비
- 취득 관련 세금
- 금융 수수료·이자·보증료
- 분양·마케팅·중개비
- 계산 가능한 보유세·부가세 현금효과

법인세처럼 사업 종료 후 세후 수익에 적용하는 항목은 세전 원장과 분리하되, 세전/세후 결과를 명확하게 구분한다.

### 2.5 사용되지 않는 입력을 받지 않는다

- 입력 필드는 계산식·검증식·보고서 중 최소 하나에 실제로 연결되어야 한다.
- `leaseUpMonths`, `salesPaceMonthlyPct`처럼 입력을 받아도 결과가 변하지 않는 필드는 연결 전까지 화면과 필수 출처 게이트에서 제거한다.
- 입력을 추가할 때는 값 변경에 따른 단조성 또는 영향 회귀 테스트를 함께 추가한다.

## 3. 취득대금 데이터 계약

### 3.1 기본 구조

```ts
interface AcquisitionCostContract {
  grossPurchasePriceManwon: number;
  landAllocationManwon?: number;
  existingBuildingAllocationManwon?: number;
  buildingVatManwon?: number;
  brokerageAndLegalManwon?: number;
  tenantRelocationManwon?: number;
  allocationStatus: "unallocated" | "contract" | "appraisal" | "statutory";
}
```

### 3.2 불변식

안분값이 존재할 때:

```text
토지 배분가액 + 기존 건물 배분가액 = 부가세 제외 총 취득대금
```

사업 원장 취득 단계:

```text
취득 단계 현금유출
= 총 취득대금
+ 건물분 부가세 현금유출
+ 중개·법무 등 부대비용
+ 명도·임차인 정리비
+ 취득 관련 세금
```

철거비는 취득대금 안분과 별도로 공사 준비 단계에 반영한다.

### 3.3 기존 데이터 호환

기존 `parcel.acquiredPrice`는 마이그레이션 기간 동안 `grossPurchasePriceManwon`의 별칭으로만 읽는다. 기존 값을 자동으로 순수 토지가로 해석하지 않는다.

안분자료가 없으면:

- 총사업비에는 총 취득대금을 사용할 수 있다.
- 토지/건물별 취득세와 부가세를 확정 계산하지 않는다.
- 화면에는 `총액 확보 · 안분 미확정`으로 표시한다.

관련 기준:

- [지방세법](https://www.law.go.kr/LSW/lsInfoP.do?lsId=001649)
- [지방세법 시행령 제19조 부동산 등의 일괄취득](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=286395)
- [부가가치세법](https://www.law.go.kr/LSW/lsInfoP.do?lsId=001571)

## 4. Stage 2 → Stage 3 Geometry Contract

### 4.1 Stage 3가 소비해야 하는 값

Stage 3는 대표 Geometry Snapshot과 동일한 버전의 아래 값을 직접 소비한다.

```ts
interface FinancialGeometryContract {
  projectId: string;
  scenarioId: string;
  scenarioVersion: number;
  geometryHash: string;
  aboveGroundConstructionAreaSqm: number;
  basementConstructionAreaSqm: number;
  farCountedAreaSqm: number;
  saleableAreaSqm: number;
  rentableAreaSqm: number;
  parkingAreaSqm: number;
  commonAndCoreAreaSqm: number;
  providedParkingCars: number;
}
```

### 4.2 금지사항

- `대지면적 × 용적률`로 실제 공사면적을 대신하지 않는다.
- Stage 2에서 확정한 주차·코어를 Stage 3 일반 비율로 다시 차감하지 않는다.
- 지하층을 공사비에서 누락하지 않는다.
- Geometry hash가 다르면 구형 금융 결과로 대체하지 않고 계산을 차단한다.

용적률 산정 면적과 실제 공사 연면적은 다르다. 지하층과 일정 주차 면적은 용적률 산정에서 제외될 수 있으므로 서로 다른 필드로 유지한다.

## 5. 비교사례 계약

### 5.1 취득대금 검증

허용 사례:

- 토지 거래: 거래금액 ÷ 토지면적
- 기존 건물 포함 단독·다가구 거래: 거래금액 ÷ 대지면적, 단 `property-acquisition-proxy`로 표시

금지 사례:

- 아파트 전유면적 평당가를 토지 취득대금에 사용
- 단독·다가구 연면적 평당가를 토지 평당가로 사용
- 지목·용도·면적 기준이 다른 사례를 하나의 중앙값으로 혼합

### 5.2 신축 건물 매각가 검증

- 통매각은 거래 총액 ÷ 실제 연면적 기준 사례를 사용한다.
- 호별 분양은 전용/공급면적 기준과 상품 유형을 별도로 관리한다.
- 토지 평당가를 건물 매각 ㎡단가로 전환하지 않는다.

### 5.3 검증 상태

최소 3건 선택은 품질 보증이 아니다. 다음을 함께 저장한다.

- 거래 유형
- 면적 기준
- 대상과의 용도 일치
- 같은 동/구 여부
- 거래일
- 준공연도
- 면적 차이
- 도로·입지·권리관계 미보정 여부
- 채택/제외 사유

## 6. 금융 원장 규칙

### 6.1 자금조달

다음 구조를 고정하지 않고 출처 기반으로 선택한다.

- 토지 전액 자기자본
- 브릿지론
- 토지담보대출
- 본 PF 전환
- 이자 자본화 또는 자기자본 납부
- 금융 수수료·보증료·이자유보계정

`LTC`와 금리 두 값만으로 금융기관 약정이 확인됐다고 표시하지 않는다.

### 6.2 공정과 매출 회수

- 공사비 균등 집행과 분양 10/60/30은 공개된 초기 프로필일 뿐이다.
- 사용자 입력 분양속도와 임대 안정화 기간은 월별 원장에 실제로 연결한다.
- 임대 자산의 NOI는 임대료에서 공실뿐 아니라 계산 가능한 운영비를 차감한다.
- 운영비가 없으면 `NOI`가 아니라 `공실 반영 임대수입`으로 표시한다.
- DSCR는 영구대출의 부채상환액과 안정화 NOI가 모두 있을 때만 계산한다.

## 7. 세금 규칙

- 취득세는 토지·기존 건물 안분과 취득 주체·자산 성격이 없으면 미산정한다.
- 신축 원시취득세는 실제 과세표준 범위를 확인한다.
- 토지/건물 부가세 안분, 주택 면세, 국민주택규모, 매입세액 공제 여부가 없으면 세후 결과를 확정하지 않는다.
- 법인세 기본세율 적용값은 `세무조정 전 참고`로 유지한다.
- 세금 미산정 상태에서는 `총 세부담`이라는 표현을 사용하지 않는다.
- 취득 관련 현금세금은 세전 프로젝트 원장에 포함하고, 법인세는 세후 수익 분석에 분리한다.

## 8. 출처와 승인 상태

### 8.1 상태 정의

| 상태 | 의미 |
|---|---|
| `missing` | 값 또는 출처 없음 |
| `internal-assumption` | 공개된 내부 초기값 |
| `derived-estimate` | 원문 데이터를 알고리즘으로 가공 |
| `reviewed-estimate` | 담당자가 사례·보정을 검토 |
| `source-backed` | 요구 원문과 메타데이터 확보 |
| `expert-approved` | 해당 전문 역할이 검토·승인 |

### 8.2 게이트 원칙

- 원문 파일이 있다는 이유만으로 값의 단위·범위·관련성이 검증된 것으로 보지 않는다.
- 출처 게이트는 필드별 최소·최대, 단위, 기준일, 허용 문서, 대상 프로젝트를 검증한다.
- 0이 가능한 필드와 반드시 0보다 커야 하는 필드를 구분한다.
- 미산정 필수 항목이 있으면 최종 보고서에는 `예비` 워터마크와 차단 사유를 남긴다.

## 9. 자동 검증 불변식

모든 금융 변경은 아래 테스트 중 관련 항목을 포함한다.

1. 총 취득대금 안분은 총액과 대사된다.
2. 기존 건물 배분가액은 총사업비에 중복 추가되지 않는다.
3. 철거비는 총 취득대금과 별도로 한 번만 반영된다.
4. Stage 2와 Stage 3의 매각·임대·공사면적이 동일하다.
5. 지하 공사면적 증가 시 공사비가 감소하지 않는다.
6. 총원가 구성 합계가 총사업비와 대사된다.
7. 월별 현금흐름 합계가 손익과 대사된다.
8. 금리 상승 시 다른 조건이 같다면 금융비가 감소하지 않는다.
9. 취득대금 상승 시 다른 조건이 같다면 손익·NPV가 증가하지 않는다.
10. 매출 단가 상승 시 다른 조건이 같다면 손익이 감소하지 않는다.
11. 입력 필드 변경이 기대 계산 결과에 실제 영향을 준다.
12. 미사용 입력은 필수 출처 게이트에 존재하지 않는다.
13. 비교사례 대상과 면적 기준이 다르면 검증값 생성을 거부한다.
14. 세금 안분자료가 없으면 임의의 토지 세율을 총 취득대금에 적용하지 않는다.

## 10. 금지 표현

외부 검증 전에는 다음 표현을 사용하지 않는다.

- 정확한 시세
- 확정 매입가
- 법적 문제 없음
- 금융기관 승인 가능
- 세금 전체 반영
- 한국 LTC 구조 정확 반영
- 전문가 검증 완료
- 운영 가능한 확정 사업수지

대신 다음처럼 표시한다.

- 실거래 기반 참고 추정
- 내부 가정 기반 예비 계산
- 안분자료 미확정
- 금융기관 Term Sheet 확인 전
- 세무사 검토 전
- Geometry Snapshot 기반 계산

## 11. 변경 순서

### P0 — 잘못된 확정 방지

1. `acquiredPrice`를 총 취득대금으로 명확히 정의한다.
2. 기존 건물 안분이 없으면 총액에 토지 취득세율을 적용하지 않는다.
3. 가격 검증을 취득/매각 목적별 사례와 면적 기준으로 분리한다.
4. Stage 2 실제 면적을 Stage 3에 직접 전달한다.

### P1 — 실제 원장 완성

1. 취득 부대비·명도비·세금 현금흐름을 추가한다.
2. 지하·주차 공사비를 별도로 반영한다.
3. 브릿지/PF/수수료 구조를 입력 가능한 자금조달 계약으로 변경한다.
4. 분양속도·임대 안정화 기간을 월별 원장에 연결한다.

### P2 — 전문가 검증과 보고서

1. 감정·계약·견적·Term Sheet·세무검토 문서별 필드 검증을 강화한다.
2. 분야별 승인 버전과 geometry/model hash를 보고서에 잠근다.
3. 미확정 항목과 계산 범위를 출처 링크와 함께 보고서에 자동 표기한다.

## 12. Definition of Done

기능은 다음을 모두 만족해야 완료다.

- 필드 의미와 단위가 타입과 UI에 동일하게 적혀 있다.
- 원본·파생값·사용자 입력·전문가 승인 상태가 구분된다.
- 계산에 사용된 모든 값이 원장 또는 출처 패널에서 추적된다.
- 관련 회계·단조성·면적·출처 회귀 테스트가 있다.
- 전체 `pnpm test`와 `pnpm run build`가 통과한다.
- 미지원 범위와 미산정 항목이 UI와 보고서에 표시된다.
- README와 제품 문구가 실제 모델 범위를 과장하지 않는다.
