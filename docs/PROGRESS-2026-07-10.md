## 0. 제품 한 줄

ParcelGrid는 건축 계산기가 아니라, 토지를 발견한 시행사가 **무엇을 지을지 · 얼마에 사야 하는지 · 누구와 진행할지**를 판단하게 돕는 **알고리즘 기반 시행 플랫폼**이다.

흐름:

```
주소 입력 → 현황 분석 → 계획 스튜디오 → 사업성 검토 → 파트너 연결 → 보고서
```

## 1. 제품 가이드 요약 (v1)

### 1-1. 철학

| 원칙 | 내용 |
|---|---|
| 사실 ≠ 추천 | 공식 데이터·실거래·법규 = 사실 / 엔진 판단 = 추천 |
| AI 표현 금지 | LLM이 아니라 **알고리즘/엔진 추천** |
| 출처·신뢰도 | 실거래 / 건축물대장 / VWorld / 사용자 입력 / 표준값 구분 |
| 입력 ≠ 평가 | Envelope = 사용자 의도 / 비교 = 엔진 평가. **자동 덮어쓰기 금지** |
| 설명 가능 | 왜 이 층수·세대수·매입가인지 근거를 열 수 있어야 함 |

### 1-2. Project Timeline (6단계)

| Stage | 페이지 | 역할 | 사용자 질문 |
|---|---|---|---|
| **0** | 주소 입력 | 대상지 선택 | — |
| **1** | 현황 분석 | 토지·건물·법규·실거래·3D (읽기 전용) | 지금 이 땅과 건물은 어떤 상태인가? |
| **2** | 계획 스튜디오 | 추천 / 수익최적 / 법규최대 / 직접설계 | 어떤 건물을 계획할 수 있고, 어떤 안이 적절한가? |
| **3** | 사업성 검토 | 공사비·매출·PF·IRR·민감도·최대 매입가 | 돈이 되는가? 얼마에 사야 하는가? |
| **4** | 파트너 연결 | 설계·시공·감리·금융 | 누구와 진행할 것인가? |
| **5** | 보고서 | PDF/DOCX + 출처·규제 | 투자자·건축사에게 공유할 수 있는가? |

### 1-3. Stage 2 네 가지 안

| 탭 | 의미 | 생성 방식 |
|---|---|---|
| **알고리즘 추천안** | 건축적으로 균형 잡힌 기본 추천 | 법규·일조·주차·시공성 점수 |
| **수익 최적안** | 투자수익성 최고 | IRR/손익/최대 매입가 |
| **법규 최대안** | 법규·물리 제약상 최대 | 건폐율·용적률·정북일조·주차 |
| **직접 설계안** | 사용자 직접 입력 | 층수·세대·상품유형 슬라이더 |

> 권장안은 사용자 계획을 **강제 변경하지 않음**. `[이 안 적용]`으로만 반영.

### 1-4. 점수 축 (합치지 않음)

| 축 | 질문 |
|---|---|
| 건축 타당성 | 무리 없이 지을 수 있는가? |
| 투자성 | 돈이 되는가? (IRR, 손익, 최대 매입가) |
| 데이터 신뢰도 | 데이터가 얼마나 믿을 만한가? |

### 1-5. 엔진 역할

Lookup → Envelope → Buildable Area → Scenario → Parking → Feasibility → Score → Report

## 2. 지금까지 한 것

### Stage 0 — 주소 입력 ✅ 거의 완성

- `/projects/new` 주소 검색 + Kakao 자동완성
- 조회 → sessionStorage → 프로젝트 생성
- CTA: **분석 시작 → 현황 분석**

### Stage 1 — 현황 분석 ✅ 완료 (이번 세션 핵심)

**라우트:** `/projects/[projectId]/status`

| 섹션 | 구현 |
|---|---|
| ① 기본 정보 | 주소, 대지면적, 용도지역, 건폐율·용적률 상한, 공시지가, **현재 건폐율·용적률** |
| ② 기존 건축물 | 준공연도, 용도, 층수, 연면적, 세대수 (MOLIT) |
| ③ 지도 | 핀 + 실거래/역세권 레이어 (파란 필지 폴리곤 제거 — 혼동 방지) |
| ④ 기존 건물 3D | **현재 건물** 단순 매스 (대지 + 층별 슬래브 + 지하). 신축·정북일조 후퇴 없음 |
| ⑤ 알고리즘 요약 | 규칙 기반 bullet (`status-summary.ts`, LLM 없음) |

**데이터/버그 수정**
- `currentBuilding` sessionStorage → dynamic API 파이프라인
- 지적 필지 오매칭 수정 (지번 매칭 + point-in-polygon + centroid)
- 3D 단순화: 주변 건물·도로·와이어프레임 제거 (겹침/각도 혼동 해소)

**원칙 확정**
- Stage 1 3D = **기존 건축물만**
- 세대 배치·필로티·정북일조 계단식 = **Stage 2부터**

### Stage 2 — 계획 스튜디오 ⚠️ 골격 완료 / 내용 부분

**라우트:** `/projects/[projectId]/envelope` (제목: 계획 스튜디오)

| 탭 | 상태 |
|---|---|
| 알고리즘 추천 | ✅ 권장 vs 내 계획 vs 법규 최대 카드·비교표·WhyRecommend·적용 버튼 |
| 수익 최적 | ⚠️ **준비 중** 플레이스홀더 |
| 법규 최대 | ✅ 상한 지표 + 최대 매싱 3D + 비교표 |
| 직접 설계 | ✅ 기존 Envelope STEP 1~5 + MassingView |

**네비**
- WorkRail: 현황 → 계획 스튜디오 → 대시보드 …
- Stage 1 ↔ Stage 2 링크 / CTA

**UI 결정 (2026-07-09)**
- 비교표에서 **건축 타당성 점수(우수/양호) 숨김** — 엔진 내부 선택용만 유지
- 이유: 내 계획이 더 좋은데 둘 다 “우수”로 보여 오해 유발
- 화면에 남길 것: 층수·연면적·용적률(실현/상한)·세대·일조·주차·시공성·법적 리스크

**권장안 로직 (참고)**
- 실현 용적률 = 연면적 ÷ 대지 (법정 상한 아님)
- 1~최대 층수 후보 → Buildable Area(정북일조·이격) → 점수 최고 = 권장
- 좁은 필지에서 33%처럼 낮게 나오는 것은 **형상·일조 후 실제 짓는 규모** 때문

### Stage 3 — 사업성 검토 ⚠️ 부분 (대시보드에 분산)

- `/projects/[id]` 대시보드: KPI, 시나리오 비교, 최대 인수가, 가정 편집
- `/overrides` 가정 편집
- 투자성(IRR 등)과 건축 타당성 분리 — 철학은 반영됨
- **전용 Stage 3 페이지·타임라인 통합은 미완**

### Stage 4 — 파트너 연결 ❌ 없음

### Stage 5 — 보고서 ⚠️ 골격만

- `/report` 존재, 가이드 수준(출처·규제·3D·실거래 통합) 미달

### 이전 세션에서 이미 있던 것 (2026-07-08)

- Envelope 2열 UI, 정북일조·주차·Buildable Area 엔진
- 권장안 점수 기반 선택 (하드코딩 층수 제거)
- 권장안 적용/되돌리기

   - 상단/좌측에 Stage 0~5 진행 표시 (가이드 우선순위 1번)

3. 건축 타당성 vs 투자성 축을 화면에서 명확히 분리
