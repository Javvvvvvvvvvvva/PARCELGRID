# 평면·사업성 연결 계약

작성일: 2026-10-24 (America/Chicago)

## 범위

Stage 2의 실내·차량 동선 예비 검증에 사업성 연결 탭을 추가한다. 저장된 주거층 평면에서 조건부 비교안을 자동 계산하되, 저장안 변경은 사용자가 최신 비교 내용을 확인하고 반영할 때만 수행한다. 전체 주거층 또는 지정한 한 층을 선택할 수 있다.

## 면적과 계산

- 세대 유효: 세대 외곽 치수에서 부모 구획의 가정 벽 두께를 뺀 면적.
- 상세 실 합계: 유효한 상세 구획의 방·거실·주방·욕실·세대 내부 통로 유효면적 합계.
- 두 값 모두 법정 전용면적이 아닌 설계 가정이다. 반영 시 매각/임대 산정 면적과 주차 전용면적 입력을 같은 가정값으로 두고, 주차 근거를 user-entered로 표시한다. 비수익 주거는 매출을 만들지 않는다.
- 총 층면적, 외곽, 높이, 세대수, 제공 주차대수는 유지한다. 잔여는 기존 공용 구역 비율에 배분하며 공용부·벽체·미배정 공간을 포함한다.
- 묶음 세대 구역은 개별 세대 구역으로 분리한다. 실제 세대마다 다른 유효면적을 주차 산정 엔진에 전달한다.
- 기존 calculatePlanningScenario, 주차 규칙, 여섯 수익 풀과 Stage 3 areaContract를 재사용한다. 이익률은 이익/매출이며 IRR이 아니다.
- 공사비는 기존 연면적 단가, 재료 및 세대수 가정에 따른다. 총면적을 줄여 공사비를 인위적으로 낮추지 않는다. 벽체·문·설비 수량 및 현장 견적 변화는 미반영이며 0원 확정이 아니다.
- 기존 실거래 관측 단가는 대상 면적/층 조건을 다시 검사한다. 조건 불일치는 기존 공통 가정 단가로 돌아가고 비교안에 경고한다.

## 안전 장치

현재 형상 입력의 기준키와 층 외곽/프로그램 총면적을 검사한다. 경계 없음, 오래된 형상/부모/상세 실, 겹침, 잘못된 문 연결, 지원하지 않는 혼합층, 중복 ID 등은 반영을 막는다. 부모 검증 중 전용면적·공용면적 예산 불일치만 재배분 대상이며 실제 형상 실패는 면제하지 않는다.

구역 ID만 바뀌는 경우 세대·현관·상세 실 참조를 함께 재연결한다. 이미 오래된 상세 실/지상 출구 기준은 새 기준으로 덮지 않는다. 정상 지상 출구는 물리적 형상이 동일할 때만 기준을 갱신한다.

미리보기는 저장하지 않는다. 반영은 현재 저장 상태와 비교 sourceKey를 다시 대조한다. 면적 기준/대상/입력이 바뀌면 확인 체크가 해제된다. 변경 시 기존 대표 형상·사업성 스냅샷 무효화 경로를 그대로 사용한다.

최근 10건의 반영 이력은 원본 구역과 참조 매핑, 전후 기준키, 면적/이익 증감을 보존한다. 되돌리기는 반영 이후 평면·프로그램·주차·코어가 바뀌지 않은 마지막 활성 건에만 허용하며, 복원 결과가 원본 기준키와 일치해야 한다. 키는 변경 감지용이며 서명·전문가 승인 증명이 아니다.

Workspace 형식 검증, 잠금 편집 보호, 복제 시 이력 초기화를 포함한다. 공식 경계·법정 피난 적합성·허가·전문가 승인은 자동 승격하지 않는다.

## 검증

- src/tests/layout-finance.test.ts: 정상/실패, 공사비·총면적 보존, 상세 실, 묶음 세대, 매각/임대/비수익, 관측 단가 해제, 오래된 비교 차단, 순차 복원, Workspace, Stage 3 계약.
- 실제 투영 좌표의 미세한 맞닿음 오차는 Turf clipping 입력에만 1e-8 m 격자를 적용한다. 저장 좌표/면적은 수정하지 않으며 기존 1e-5 판정 허용오차보다 작다. 실내·차량·피난 회귀도 함께 검증한다.
- artifacts/layout-finance-2026-10-24/browser-smoke.cjs: 독립 브라우저에서 합성 경계만 사용한다. 서버 저장은 차단하며 실제 쌍문동 경계나 사업성 결과로 해석하지 않는다.

## 남은 외부 확인

공식 경계와 도로/출입구, 건축 용도·허가 조건, 법정 전용/공용 면적 산정, 창호·채광·환기·방화·계단 상세, 구조·설비·현장 견적은 별도 원문/실측/전문가 확인 대상이다. 이번 기능은 초기 설계 대안의 조건부 사업성 연결이며 인허가 판정이나 실제 견적서가 아니다.
