## 현재 결정과 첫 발주

사용자 확인(2026-10-27): 연결된 건축사·견적/QS·세무 검토자와 실제 도면·견적 자료는 아직 없다. 아래는 견적 요청 준비이며 선정·계약·결제·자료 외부 제공 승인이 아니다. 예산과 일정도 미정이다.

첫 의뢰는 **쌍문동 281-23 한 필지의 독립 사전검토**로 제한한다. 용적률 200%/250%와 4/6/8세대의 여섯 조합은 비교 가정이며, 어느 조합도 허용 또는 실현 가능하다고 미리 확정하지 않는다. 전문가가 불가능 또는 근거 부족으로 제외한 조합도 결과물에 이유를 남긴다. 실시설계·허가대행·구조 안전 확인·시공 계약은 별도 범위다.

1차 파일럿의 결과 형식과 수정·재검토를 확인한 후 실제 10필지로 확대한다. 먼저 10필지를 일괄 계약하거나 렌더링·홍보물을 발주할 필요는 없다. 가능하면 각 분야 2~3곳에 **같은 범위표**로 견적을 받아 비교하되, 비용·공급자·일정은 실제 제안서 수령 전 추정 확정하지 않는다. 건축 검토자가 연계 업체를 소개한 경우에도 견적 검산의 독립성과 이해관계를 기록한다.

## 전달 패키지와 수령 체크

내부에서 준비할 패키지는 `사례 식별/권한`, `원자료 목록과 누락`, `동일 버전 계획·도면`, `수량·견적`, `재무 입력·원장`, `검토 질문·답변`의 여섯 묶음으로 구성한다. 원본 파일명·문서 해시·기준일·계획 버전·검토 스냅샷 키를 목록으로 대조한다. PDF 의견서와 함께 편집 가능한 도면/수식 계산표를 계약 범위에 명시하고, 수신 후 실제 파일 열기와 숫자 대사를 한다.

수령 상태는 `미요청 → 요청 승인 → 전달 → 검토 중 → 지적 수령 → 수정 → 재검토 → 분야 인수`로 기록한다. 자료 부족·비교 불가·기하 생성 실패는 통과가 아니다. 분야 인수는 관할 허가나 최종 제품 출시 인수와 다르다. 이번 단계에서 외부 업체에 발송·발주한 건은 **0건**이다.

## 요청 목적

PARCELGRID의 건축 사전검토와 사업성 결과를 실제 원자료 및 독립 계산으로 대조한다. 코드 작성자 또는 AI의 자체 확인을 외부 전문가 검산으로 계산하지 않는다. 검토 결과와 검토자 자격 확인, 관할 인허가 상태는 별개 기록이다.

우선 소수 사례로 전달 형식과 오차 기록을 교정한 뒤, 공식자료가 확보된 실제 필지 최소 10건을 검산한다. 합성 실패·경계 사례 최소 20건은 별도 목록으로 관리하며 실제 필지 수에 포함하지 않는다. 쌍문동 281-23의 공식 경계·허가·전문가 승인은 현재 미확정이고, 제공되지 않은 자료를 추정으로 확정하지 않는다.

3. 계획 ID·버전·대표 Geometry 해시, 원본 계획 및 검토 스냅샷 키. 인계 화면의 검토 자료 JSON과 도면/PDF를 같은 기준 버전으로 제공.
4. 층·용도·세대·실·문·피난·주차·차량 제원 및 가정. 모델 검사를 공식 적합 판정으로 표시하지 않음.
5. 수량·공종·기본 포함액·교체 견적·출처·시점·제외 범위. 내부 가정 단가와 실제 제출 견적을 구분.
6. 재무 원본 입력, 세전/세후 정의, 월별 원장, 비교안 및 하방 시나리오. 예상 수익을 보장 수익으로 표현하지 않음.
7. 담당 분야별 질문, 알려진 실패/제한, 검토 마감과 응답 형식. 파일 수신 프로그램과 버전 기록.

현 상태의 합성 검증 자료는 전달 형식 예시일 뿐 실제 도면·견적의 검산 자료가 아니다. 원문 첨부와 서버의 검토 이력이 일반 JSON 인계에 모두 포함된다고 가정하지 말고 실제 수신 파일 목록을 대조한다.

## 검산 결과 양식

각 지적은 다음 필드를 포함해야 한다.

`사례 ID | 검토 분야 | 계획 버전 | 스냅샷 키 | 원문/도면 위치 | 규칙·기준일 | 값의 정의·단위 | 독립 계산값 | 프로그램 값 | 차이 | 원인 | 심각도 | 수정 요구 | 재검토 결과 | 검토자·일자`

- 면적은 0.01㎡, 동일 정의 금액의 화면/보고서는 표시 최소 단위1 이내 대사를 목표로 한다. 법정 허용오차나 전문가 판단을 이 수치로 대체하지 않는다.
- 입력·정의가 달라 비교할 수 없으면 `비교 불가/자료 필요`로 기록한다. 빈 칸을 통과나0으로 해석하지 않는다.
- 중요 계산 오류, 자료 유출/유실, 거짓 승인·허가 표시, 중복 과금/게시 및 핵심 업무 실패는 출시 차단 대상이다.
- 수정 후 같은 사례를 다시 실행하고 이전/이후 결과와 재검토 원문을 남긴다. 관련 입력이나 엔진 기준 변경 후에는 기존 의견의 적용 가능성을 다시 확인한다.
- 외부 검토 결과를 받은 뒤 메인이 근거·버전·수정 여부를 대조하고 사용자가 최종 인수한다. 단순 제출/수령은 합격이 아니다.

## 외주·자료 제공 승인

견적 요청에는 사례 수, 분야별 범위, 산출물 형식, 독립 검산 방식, 재검토 횟수, 일정, 비용·세금·지급 조건, 비밀유지, 자료 이용/보관/삭제, 결과물 권리와 책임 범위를 포함한다. 먼저 합성 또는 비식별화된 최소 자료로 가능 여부를 확인한다.

실제 고객 자료의 외부 제공, 유료 평가 계정, 외주 계약/발주/결제는 사용자 승인 전 실행하지 않는다. 비밀번호나 API 키는 자료 패키지에 넣지 않는다. 검토자에게 필요한 최소 접근만 부여하고 검토 종료 시 접근 회수와 자료 처리 결과를 확인한다.

## 사용자 준비 항목

- 보유 중인 검토자·파트너의 연결 가능 여부와 담당 분야.
- 실제 도면·공식자료·견적이 있는 사례 목록과 사용/제공 권한. 미확정 자료는 그대로 표시.
- 외부 발주가 필요한 경우 승인 가능한 예산·일정·지역/지원 범위.
- 선두 서비스 최소2개의 적법한 평가 계정 또는 동일 과제 실행 결과. 기능 소개 자료만으로 동등성을 판정하지 않음.

이 정보가 없더라도 내부 기능·회귀·보안·성능 작업은 계속 진행한다. 다만 실제 외부 검산·사용자 평가·경쟁 과제 및 최종 인수를 완료했다고 선언할 수는 없다.
