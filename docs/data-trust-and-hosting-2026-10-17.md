# 데이터 신뢰성 수정 및 배포 준비 — 2026-10-17

현재 사용자 작업(기준 커밋 `5b1fee5806ec3fcdb36733c3772dc8f2fddc6f90`, package 0.1.0)을 보존한 선택적 수정이다. 공개 master `9ca74d4d811374f3568d675c72459d012413b079`의 건축물대장 클라이언트·근거 표시만 통합했고, 사용자 인증/RBAC·서버 Workspace·재무 작업은 유지했다. 전체 master 병합이나 배포 완료를 의미하지 않는다.

최신 추가 검증은 문서 끝의 “추가 검증 및 오류 경계 수정” 절을 따른다. 앞부분은 작업 당시의 검사 기록이다.

## 바뀐 동작

- 데모 PNU와 같은 실제 필지를 입력해도 시드로 바뀌지 않는다. 서버 Workspace를 먼저 검증하고, 404일 때 일치하는 입력 또는 시드를 선택한다. 401/403/503은 시드로 우회하지 않는다. 데모 배지·저장 제외는 ID 대신 실제 로드 출처를 따른다.
- MOLIT 건축물대장 HTTP 200 오류 XML, 인증 거절, 누락 페이지, 정상 0건을 구분한다. 정상 0건도 현장 빈 토지 확정은 아니다. 표제부·층별·전유공용의 조회 시각, 원본 ID, 페이지/건수/오류 근거를 현황·입력·보고서에서 볼 수 있다. GIS 건물 보완은 별도 출처로 남는다.
- 실거래는 유형/월별 완료·실패와 실패 분류를 반환한다. 조회 실패는 거래 0건으로 확정하지 않는다. 불완전 범위는 자동 가격 보정에서 제외하며, 남은 관측 거래와 실패 근거는 보존한다. 캐시 재사용 시 최초 원문 수신 시각과 현재 집계 시각을 구분한다.
- 이 근거는 계산→계획 재계산→Stage 3 저장→인계→보고서에 유지된다. 전체 조회 완료 근거 없는 사례 수는 인계의 매각 사례 근거로 충족되지 않는다. 전문가 승인 식별자는 기존 전체 계산 본문 해시를 사용하므로 조회 근거 변경도 승인 대상 변경에 반영된다.
- VWorld 호출 도메인은 설정값을 사용한다. 잘못되거나 용도지역 없는 응답은 정상 법규 출처로 바꾸지 않는다. Kakao/VWorld 제공자 오류 본문을 예외 메시지에 그대로 포함하지 않는다.
- `/system/readiness`와 API는 설정 확인임을 명시한다. `kind=configuration-only`, `liveConnectivityVerified=false`이며 키 존재만으로 실제 연결 성공을 주장하지 않는다.
- `.dockerignore`는 환경 파일·사용자 저장 데이터·Git·개발 결과물을 빌드 컨텍스트에서 제외한다. Dockerfile의 public 지도 키 빌드 인자만 준비했다. 실제 키 값은 포함하지 않았다.

## 검증 범위와 남은 한계

실제 키 없이 잠금파일 그대로 설치한 분리 사본에서 lint, TypeScript, Vitest, Next production build를 검증한다. 합성 HTTP 응답과 기존 시드/계산 회귀 테스트는 응답 오류 분류·근거 전파·계산 일관성을 확인하지만 외부 공급자의 실제 데이터·접근 허용 여부를 검증하지 않는다.

후속 승인 후 Kakao REST·JS 지도와 MOLIT 건축물·매매 API의 실제 응답을 확인했다. VWorld는 직접 호출에서 소켓 종료, 앱 호출에서 HTTP 502로 실패했다. 한국/미국 네트워크 비교, 인쇄/PDF, 실제 PostgreSQL migration/조직 권한/동시 수정/백업 복구, 외부 저장소, 운영 부하와 API 한도는 아직 미검증이다. 후속 사용자 Mac Chrome 검증에서는 키 없는 데모의 3D 매스 렌더와 근거 차단 화면을 확인했다. VPN·접근 차단 원인도 확인되지 않았다. 인증 거절을 다른 경로로 우회하지 않는다. 가격 모델은 기존 실험적/외부 미검증 모델이며, 수동 법규값과 가격 가정을 실제 원문·전문가 판단으로 대체하지 않는다.

도로 등 선택적 VWorld 문맥 조회 일부는 기존 빈 배열 fallback을 유지한다. 도로 참고선이 없으면 인계 근거가 부족해지며, 이를 실제 도로 없음으로 판단해서는 안 된다. 기존 저장 프로젝트는 자동 재조회하지 않는다. 이전 시드/저장 자료에 조회 근거가 없으면 미확인으로 표시하고 새 주소 조회를 통해 근거를 확보해야 한다.

## 현재 구조에 맞는 배포 조건

현재 코드 변경을 최소화하는 후보는 **단일 Node 24/Docker 서비스 + 영구 디스크 + PostgreSQL**이다. 후속 확인에서 기존 Vercel Hobby 프로젝트를 찾았지만, 해당 서버리스 환경에 현재 파일 저장 코드를 그대로 배포하면 운영 저장을 보장할 수 없다. 외부 리소스는 생성하지 않았다.

- 앱 시작: `pnpm start` (production build 필요). 원문·렌더 파일에 영구 볼륨을 연결한다.
- `SOURCE_DOCUMENT_STORAGE_DIR`, `CONCEPT_RENDER_STORAGE_DIR`는 영구 볼륨 경로를 사용한다. Workspace/감사 원장은 운영 PostgreSQL을 사용하고 최신 migration과 조직 멤버십을 검증한다.
- `PROJECT_WORKSPACE_STORAGE_DIR`, `AUDIT_LEDGER_STORAGE_DIR`는 로컬 fallback 경로다. 다중 인스턴스 저장/동기화 보장으로 해석하면 안 된다.
- `SITE_ACCESS_ACCOUNTS_JSON`과 32자 이상의 `SITE_ACCESS_SESSION_SECRET`이 없으면 production 인증이 준비되지 않는다. 코드의 로컬 인증 예외를 운영에 켜지 않는다.
- Docker 엔진 연결을 확인했지만 이 Mac의 `/var/run/docker.sock`이 없어 컨테이너 빌드/기동은 미실행이다. 엔진/보안 설정은 변경하지 않았다.
- 로컬 `.vercel/project.json`은 없으나 후속 사용자 Mac Chrome의 기존 로그인으로 Vercel 프로젝트를 확인했다. 공개 사이트도 `/access` 비밀번호 화면까지 열렸다. 새 로그인은 하지 않았다. 상세 상태는 아래 후속 확인을 따른다.

2026-10-17 공식 문서 기준, [Vercel Hobby](https://vercel.com/docs/plans/hobby)는 비상업 개인용이다. 또한 [Functions 제한](https://vercel.com/docs/functions/limitations)의 요청/응답 4.5MB 한도는 현재 Workspace 최대 10MB 및 이미지 업로드와 대조해야 한다. 현재 파일 저장을 외부 영구 저장으로 바꾸는 작업도 필요하므로 단순 재배포만으로 운영 호환을 보장할 수 없다.

[Render 무료 서비스](https://render.com/docs/free)는 영구 디스크를 지원하지 않고 재시작/유휴 종료 시 로컬 파일을 잃는다. 무료 PostgreSQL은 30일 후 만료된다. 현재 제품의 유료 판매용 장기 저장에는 맞지 않는다. 기존의 적절한 서버·DB가 있다면 추가 비용 없이 검증 가능할 수 있지만 보유 자원을 확인하기 전에는 비용 0원을 보장할 수 없다.

## 승인된 로컬 키 적용 및 실제 조회 — 완료

사용자의 “다허락하마” 승인 후 예전 Desktop `.env.local`에서 현재 `Documents/ChatGPT/percelfrid/.env.local`로 `KAKAO_REST_API_KEY`, `NEXT_PUBLIC_KAKAO_JS_KEY`, `MOLIT_SERVICE_KEY`, `VWORLD_API_KEY` 네 개의 빈 항목만 채웠다. 기존 비어 있지 않은 값은 보존하는 절차이며 이번에는 네 개 모두 빈 항목이었다. `VWORLD_ENABLED=true`로 설정했고 나머지 설정을 보존했다. 키 값은 출력하거나 Git·외부 호스팅에 올리지 않았다. 대상 `.env.local`은 Git ignore 대상임을 확인했다. 원본 환경 파일의 다른 키·계정·DB 값은 가져오지 않았다.

직접 provider probe와 사용자 Mac Chrome `http://localhost:3000`의 개발 서버에서 검사했다. 테스트 서버의 DB 연결은 사용하지 않았고, 서버 파일은 `/tmp/parcelgrid-live-validation`에 격리했다. 브라우저에 있던 같은 PNU의 기존 계획·저장본은 삭제하지 않았다. 실제 공공 데이터와 테스트 가정(대지 120㎡, 용적률 200%, 건폐율 60%, 취득가 10억원)을 함께 사용했으므로 이 수치는 실제 부지의 법정값·계약금액이 아니다.

추가 수정: 시드 좌표/경계를 실제 Kakao/VWorld 확보로 표시하지 않음; 거래 카드가 근거 미확보/완료/일부 미확인을 구분; 법정 상한 대신 검토값과 사용자 입력 상태 표시; 유효한 Stage 3 저장본 부재 시 현재 계산의 예비 표시임을 명시. 구형 현금흐름 필드 부재는 세후 결과를 만들어 내지 않고 invalid로 처리한다. 기존 저장본은 보존했다.

운영 DB가 없으면 readiness의 `deploymentGate=blocked` 및 API HTTP 503을 반환한다. **파일 fallback·기존 데이터·인증 코드를 자동 변경하지 않는다.** 이 상태를 실제 배포 검사에 연결하는 것은 아직 필요하며, 앱 전체 기동이 중지되는 것은 아니다. DB가 설정돼도 연결·migration·복구 검증 완료를 뜻하지 않는다.
