# 통합 검토 자료와 승인 결속

기준일: 2026-10-27, America/Chicago. 제품 최종 인수는 미완료다.

## 검토 단위

`review-snapshot-2026.6`은 대표안의 Stage 3 사업성 저장본, 원본 PlanningScenario(실내·상세 실·문·피난·차량 제원 및 수량 원가 포함), 전체 Geometry, 가격·재무·세무 근거와 통합 검증 결과를 같은 SHA-256 본문에 포함한다. 기존 geometryHash 또는 계획안 ID/버전만으로 실내 변경을 식별하지 않는다.

인계 보드와 보고서는 같은 생성 함수를 사용한다. Stage 3 본문에 있는 대표안과 비교안의 세무 계약을 모두 결속한다. 다른 프로젝트나 본문에 없는 계획안의 계약은 제외한다. 보고서의 비교 세후 결과가 달라져도 승인 키가 그대로 남지 않도록 한다. 비교안의 공간 검토는 해당 안을 대표안으로 저장하여 별도 자료를 생성한다.

원본 계획 변경, 문·방·피난 설정·차량 제원 변경, 계산 결과 및 근거 변경은 검토 키를 변경한다. 새 키에 대해 다시 봉인·요청·검토한다. 저장 시각만 다른 Stage 3 메타데이터와 근거의 기록 시각은 기존 규칙대로 제외한다. 계획·형상의 원본 기록은 보존한다.

## 서버 검증

- 서버는 수신한 검증 결과를 신뢰하지 않고 같은 원본으로 모델 검사를 재실행하여 본문과 대조한다. 결과나 검사 목록을 변경한 요청은 봉인 전에 거부한다.
- 현재 통합 검증 `integrated-verification-2026.5`는 최대 32개 표시 비교안의 기본·Low·High 월별 금융, 자금 부족, 세전 손익과 Pareto 본문도 재계산한다. 범위·한도와 미확정 처리는 `CONSTRUCTION-COST-SENSITIVITY-2026.1.md`를 따른다.
- 전체 대지 조각·내부 제외 영역과 도로 이름·점 순서·좌표를 저장 형상에 대조한다. 경계 또는 도로가 누락·변경되면 주차 미대상이어도 모든 분야의 승인을 차단한다. 명시적인 빈 도로 목록의 일치는 원자료 연결 확인일 뿐, 도로의 실제 부재나 진입 허가가 아니다.
- 복합 대상 대지의 전체 업무 연결은 아직 보류 중이다. 원자료와 형상이 일치하더라도 `binding.parcel-support`가 모든 분야의 승인을 차단한다. 저장된 통과·대표안·내보내기 플래그만으로 이 지원 범위 보류를 우회할 수 없다. 전체 연결을 완료하고 회귀·사용자 검증을 확보한 후 명시적으로 해제해야 한다.
- 크기 제한 확인 후 검사를 수행한다. 봉인 조회도 본문·검증 결과·SHA-256·감사 체인을 확인한다.
- 누락된 원본을 포함한 예비 자료는 검토 요청과 수정 요청을 위해 봉인할 수 있다. 봉인은 자료의 보존과 식별이며 설계·사업성의 적합 승인이나 원문의 진위 보증이 아니다.
- 승인 API는 봉인된 통합 검증의 해당 분야 차단 항목을 확인한다. 누락·충돌이 남은 분야는 승인할 수 없다. 검토 요청·검토 시작·수정 요청은 허용한다. 요청자와 담당자 분리, 분야 역할, 상태 전이 및 감사 원장 충돌 검사는 그대로 유지한다.
- 클라이언트는 원본 객체가 바뀌는 즉시 이전 키를 사용하지 않는다. 새 SHA-256 계산을 기다리는 동안 이전 봉인 상태를 현재본 승인에 쓰지 않는다.

## 상태와 한계

모델 검사 통과, 추가 검토, 자료 누락, 충돌, 해당 없음을 구분한다. 주거 내부의 지원 수량·원가 연결은 `QUANTITY-COST-2026.1.md`를 따른다. 전체 공종 물량·독립 견적 검산은 여전히 누락이며 0원 또는 검증 완료가 아니다. 모델의 검사는 기존 기하·실내·피난·주차 엔진의 지원 범위 안에서만 수행한다. 차량의 제한된 템플릿 탐색 실패는 실제 진입 불가능의 증명이 아니다.

공식 경계·관할 인허가·전문 자격 확인은 별도 미확정이다. 앱의 역할 권한과 검토 의견 기록은 전문 자격 증명이나 법정 피난 판정이 아니다. 재무 대사는 표시값의 산술·계약 일치 검사이며 독립 전문가 검산·실제 견적·전체 재무 모델의 정답 보증이 아니다. 면적·수익·주차대수는 이 보고서를 만들거나 봉인할 때 자동 변경하지 않는다.

## 화면과 파일

인계와 보고서에 같은 통합 검증 목록을 표시한다. 유효한 대표 저장본이 없으면 미봉인 예비 점검으로 표시한다. JSON 내보내기는 동일 원본과 검증 결과, 키 및 서버 봉인 확인 상태를 포함한다. 내보낸 파일의 봉인 표시만으로 진위를 신뢰하지 말고 권한 있는 서버 원장의 같은 키와 대조해야 한다. 파일에는 고객 계획·사업성·근거가 포함되므로 외부 제공 동의와 비식별화는 별도 필요하다. 자동 외부 전송은 하지 않는다.

## 이전 자료

2026.5 이하 봉인·승인 이벤트는 감사 이력에서 삭제하거나 다시 쓰지 않는다. 현재 통합 검토의 승인 근거로 승계하지 않으며 새 원본과 검증 결과로 2026.6 봉인을 생성하고 재검토한다. 이전 키 조회가 현재 지원 봉인으로 확인되지 않는 것은 감사 기록 삭제가 아니다. 이전 검토가 진행 중이어도 다른 키에 대한 새 요청은 가능하며 이전 이력을 보존한다. 같은 키의 진행 중 검토를 임의로 초기화하지 않는다.

## 검증 기록

수량 연결 직전 2026.4 단계의 `pnpm verify` 기록: lint, TypeScript, 테스트 862개, production build 통과. PostgreSQL 통합 1개는 제외되어 실제 운영 인수로 계산하지 않는다. 통합 검사 전용 34개, Snapshot 14개, 승인 API 3개 및 검토 상태 전이 시험을 포함한다. 2026.5 수량 원가 검증과 최신 수치는 `QUANTITY-COST-2026.1.md` 및 `PROJECT_MEMORY.md`를 따른다.

격리 임시 서버의 실제 브라우저에서 원본·검사 결과 봉인, 원본을 포함한 JSON 다운로드, 인계/보고서 동일 키, 차량 제원 변경 후 새 키·새 봉인·재검토 요청을 확인했다. 1440px/390px 화면 가로 넘침과 page error는 없었다. Workspace 원격 revision 변경 시 보존된 로컬 초안을 명시적으로 버리고 최신본을 열어 변경을 확인했다. 증빙은 `artifacts/integrated-review-2026-10-26/`에 있다. 합성 사례는 실제 필지 검산 및 외부 전문가 인수로 집계하지 않는다.

브라우저 시험에서만 드러난 Next 서버 기하 연산 로딩 오류도 수정했다. `concaveman`의 CommonJS `RBush` 생성자가 RSC 묶음에서 잘못 해석되어 차량 검사가 중단됐으며, `next.config.mjs`의 서버 외부 패키지 설정으로 Node 해석을 유지했다. 수정 전 봉인은 서버 재계산 불일치로 거부되어 거짓 통과로 기록되지 않았다. 이후 실제 서버·브라우저의 동일 봉인 키를 검증했다. 기하 의존성·서버 번들 설정 변경 시 단위 시험뿐 아니라 이 실제 봉인 시험도 재실행해야 한다.
