### 운영 인수 세부 조건

독립 코드 검토에서 아래 항목을 G05/G08/G09의 필수 시험으로 지정했다. 정적 검토에서 발견한 위험과 실제 재현 결과는 구분한다.

- 서버 API뿐 아니라 같은 브라우저의 로그아웃·조직 전환·새로고침·뒤로가기·다중 탭에서 이전 조직의 계획·원문·재무 자료가 표시되거나 새 조직에 자동 저장되지 않아야 한다. 클라이언트/API 보완과 임시 계정 시험은 `CLIENT-SESSION-ISOLATION-2026.1.md`에 기록한다. 실제 운영 DB·권한 회수 시험과 단말 보존 정책은 별도 인수한다.
- 외부 검토자의 신원, 전문 자격/경력, 검토 범위·일자와 의견 원문을 해당 검토 버전에 결속한다. 앱 역할 부여나 확인 체크만으로 전문 자격을 입증했다고 표시하지 않는다.
- 출시 후보 버전에서 실제 PostgreSQL 통합 시험의 생략을 실패로 처리한다. 운영 앱 DB 계정이 불변 기록 트리거를 해제하는 권한을 갖지 않는지 확인한다.
- 역할 강등·계정 비활성화·유출 세션 폐기·서명 키 교체·DB 장애를 시험한다. 채택한 배포 구조에서 재시작·다중 인스턴스·위조 전달 헤더로 로그인 제한을 우회할 수 없어야 한다.
- 재배포 후 DB·첨부·렌더가 유지되고, 채택한 다중 인스턴스 환경에서도 같은 권한으로 접근되어야 한다. 데이터 손실 허용시간(RPO)과 복구시간(RTO)을 운영 범위에 맞게 고정하고 별도 환경에 실제 복원한다. 상태 점검의 HTTP 200은 이 시험의 대체 증거가 아니다.
