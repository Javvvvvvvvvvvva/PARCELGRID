# 예비 실내 도면 인계 계약

`interior-drawing-export-2026.1`, 2026-10-29.

- 현재 원본에 결속된 예비 분석 기준안 또는 기존 엄격 대표안만 내보낸다. 원시 형상·면적·실·문·피난·주차를 통합 검증기로 다시 검사한다. 키만 재작성한 변조는 허용하지 않는다.
- ZIP은 `interior.dxf`, `metadata.json`, `quantities.json`, `README-KO.txt`를 포함한다. 층 외곽·세대·공용부·상세 실·개구부·계단 예약 공간·피난 후보를 구분한다.
- DXF 좌표는 미터, X=동쪽, Y=북쪽, Z=계획 층 바닥 높이. 3D POLYLINE 꼭짓점에 높이를 명시하고 폐합점도 반복한다. 객체 ID, 원본 ID, SHA-256 입력 연결값과 전체 입력 근거를 JSON에 보존한다.
- 개구부 선분은 문짝/문 여닫힘이 아니다. 구획선은 벽체 솔리드/구조체가 아니다. 계단 예약 공간은 실제 계단 설계가 아니다. 법정 피난거리·방화·설비·채광·접근성은 미확정이다.
- 수량은 기존 수량 엔진의 포함/제외 기준을 따른다. 겹치는 개념 구획선의 길이를 단순 합산해 벽 물량으로 쓰지 않는다. 면적·수익·주차대수·전문가 승인에는 자동 반영하지 않는다.
- 최대 5,000객체/20MB. 계정 잠금·계획 선택 변경·기준안 해제·원본 변경 시 내보내기를 차단한다.
- 통합 재검사와 DXF/ZIP 생성은 별도 Worker에서 실행한다. 20초 hard stop, 사용자의 취소, 선택·원본·대표·세션·페이지 변경은 Worker를 종료하며 늦은 결과를 내려받지 않는다. UI 스레드로의 무거운 동기 fallback은 없다. 반환값의 입력키·파일명·객체수·바이트 상한을 확인한 뒤 현재 원본과 다시 대조한다.

## 실제 수신기 검증

`artifacts/interior-drawing-2026-10-29/`의 합성 3층 사례: 56객체/32레이어를 FreeCAD 1.1.4로 열어 모든 객체의 좌표·높이·길이·폐합·면적을 대조했다. FCStd 저장/재열기도 동일했다. 실제 production 화면 PC1440/모바일390에서 내려받은 ZIP 각각에 같은 검사를 수행했다.

FreeCAD 기본 DXF 재출력은 폴리라인을 198개 LINE으로 분해하고 레이어명을 잃는다. 각 선분의 XYZ/길이와 중복 개수는 보존되지만 레이어/객체 식별자의 왕복 보존은 입증하지 못했다. 원본 DXF와 metadata를 인계 기준으로 보존한다. 다른 CAD·실제 전문가 인수는 아직 없다.
