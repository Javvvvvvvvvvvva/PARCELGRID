# 기본 공사단가와 월별 하방 위험

기준일: 2026-10-26, America/Chicago. 내부 모델 재현이며 실제 견적·조달 승인이나 독립 전문가 검산이 아니다.

## 계산 계약

`construction-cost-ledger-2026.1`은 같은 부지·시나리오에서 기본 공사단가를 0.85배, 1배, 1.2배로 바꾸어 `calculateScenario`를 세 번 실행한다. Low/High는 예시 스트레스이며 시장 신뢰구간, 확정 견적, 최악의 손실 한도가 아니다. 매출·면적·주차·기간·금융 조건은 고정한다.

수량 계약이 있으면 `QUANTITY-COST-2026.1.md`에 따라 교체 견적액은 고정하고, 기존 포함액을 제외한 기본 공종 비용만 단가와 함께 증감한다. 외장재 증감과 추가 세대 가산액도 고정한다. 물량·단가의 원시 정밀도를 유지하며 각 결과의 표시 경계에서 만원 단위 반올림한다. 음수 최종 직접 공사비는 0원으로 숨기지 않고 입력 오류로 거부한다.

각 경우에 직접 공사비, 설계·감리·인허가 비용, 예비비를 계산한 뒤 동일 월별 원장을 다시 실행한다. PF 이자·수수료·신탁비, 세전 총사업비·손익, 필요 자기자본·부족액·최초 부족월, IRR/NPV, 최대 자금 노출과 자기자본 현금흐름을 보존한다. IRR의 수치해가 없거나 단일 값이 아니면 수익률 숫자를 제시하지 않는다. 기존 장기보유 계산은 엔진 안에서 유지하지만 이 비교의 목적은 안정화 매각 세전 결과이며 장기보유·세후 비교를 대신하지 않는다.

기존 `이익 +/- 공사비 비율` 근사치는 제거했다. 호환용 `profitAtLowCost`, `profitAtHighCost`는 실제 월별 결과이고 `constructionCostLow/High`는 직접 공사비만 뜻한다. 간접비와 예비비를 섞은 금액을 직접 공사비로 표시하지 않는다.

## 실행과 미확정

- `calculateScenarioWithCostSensitivity`를 최종 프로젝트 계산에 사용한다. 반복 손익분기·인수가 탐색은 단일 `calculateScenario`를 유지해 모든 내부 반복의 비용을 세 배로 만들지 않는다.
- 기본 입력이 잘못되면 기본 계산부터 거부한다. 특정 스트레스 입력만 한도를 벗어나면 그 경우는 `unavailable`이고 기본 계산은 유지한다. 없는 손익을 0원 또는 기준 손익으로 대체하지 않는다.
- `scenario-decision-pareto-2026.4`는 실제 High 세전 손익으로 하방 축을 비교한다. High가 없으면 필수 비교값 누락으로 해당 후보를 순위 자격에서 제외한다. 기준 손익이 좋은 안도 고원가에서 자금 부족일 수 있으므로 각 경우의 부족 상태를 별도로 표시한다.
- `ProjectComputed.meta.version`은 `v223`이다. 구버전 결과를 자동 덮어쓰거나 고객 계획을 수정하지 않는다. 기존 저장본은 재계산·저장해야 한다.

## 보고서와 봉인

보고서는 `verifiedConstructionCostSensitivity`로 현재 원시 부지·계획을 재계산하고 저장된 민감도 본문 전체와 정확히 대조한다. 버전 문자열만 믿지 않는다. 오래된 단순 범위, 변경 전 원가·금리·취득가, 조작된 원장·금액은 표시하지 않고 재계산을 요구한다. Low/Base/High의 비용, 금융, 자금 부족, 수익 지표를 같은 정의로 표시한다.

`integrated-verification-2026.3`의 `binding.monthly-finance`는 대표안뿐 아니라 표시된 비교안 전체의 기본·Low·High, 호환 금액, 월별 현금흐름과 Pareto 본문을 다시 계산한다. 후보 32개 및 기존 원시 입력 한도 안에서만 수행하고 한도를 벗어나면 미검증으로 남긴다. 누락·불일치는 모든 분야의 승인 차단 항목이다. 전체 BOQ/QS 미검증도 계속 별도로 남긴다.

독립 코드 검토 후 비교 대상을 전체 ScenarioVM으로 확장했다. 자기자본·PF·수익률·배수·보유/대출 지표 등 표시 재무 결과와 분기 현금흐름도 대사한다. 실제 분기 계산 입력 `meta.calculationStartDate`를 보존·봉인하며, 시작일이 없는 구형 본문은 재계산을 요구한다. 저장 시각과 시작일을 혼동하지 않는다. 월말 시작일에 `Date.setUTCMonth`가 짧은 달을 넘기던 결함도 달 단위 귀속으로 수정했다.

음수 공사비 거부를 추가하면서 기존 스트레스 탐색의 0원 단가 시험이 자재비 차감액이 있는 정상 기준안을 중단시키는 회귀를 독립 검토에서 발견했다. 공통 직접 공사비 계산으로 유효 단가 하한을 먼저 구하고, 스트레스/구조 개선 탐색은 그 하한과 입력 상한 안에서만 수행한다. 별도 이름이 있는 +10% 등 충격 자체가 한도를 벗어나면 수치를 축소하거나 대체하지 않고 실패를 알린다. 화면의 실행 중 상태는 `finally`에서 해제한다.

현재 봉인은 `review-snapshot-2026.6`이다. 2026.5 이하의 봉인·승인 이력은 보존하되 현재 검사 기준의 승인으로 승계하지 않는다. 최신 입력으로 재계산·재봉인·재검토한다. 봉인은 본문 식별과 보존이며 시장 가격이나 법적 적합의 승인 표시가 아니다.

## 내부 증빙

- 전용 민감도 회귀 44개: 독립 호출 대사, 이자·수수료 2차 효과, 선분양, 자금 부족 전환, 금리·원가 0, 단가 상한, 고정 차감액의 음수 경계, 수량 견적·소수 면적, 조작·변경·JSON 키 순서 및 하방 순위.
- 통합 검증 회귀: 기본 금액·저원가·고원가·월별 배열·원시 입력·비교 순위·대표 표시 변경 및 비대표안 변조, 구버전·후보 한도.
- `artifacts/cost-sensitivity-2026-10-26/`: 합성 브라우저 입력과 실제 서버 봉인 JSON, 1440px/390px 화면, 구버전·stale·계산 불가 상태 검증. 고객 자료와 실제 시장 단가를 사용하지 않았다.
- 실제 DB 재검증은 `artifacts/postgres-revalidation-2026-10-26/`에 환경 조사만 기록했다. 실행 중인 기존 VM의 SSH 접근 실패, 로컬 서버 바이너리 부재로 최신 통합 시험은 미실행이다. 2026-10-17 실증을 최신 시험 통과로 간주하지 않는다.

전체 `pnpm verify`는 테스트 1064개 통과, PostgreSQL 통합 1개 제외, ESLint·TypeScript·production build 통과다. 실제 브라우저는 준비 조건 차단을 포함한 6개 묶음 검사를 완료했고 page error 및 PC/모바일 가로 넘침은 없었다. 이전 QA의 읽기 전용 보고서에서 봉인 버튼을 찾던 시험 구성은 인계 화면의 실제 봉인 버튼을 사용하도록 수정한 뒤 재실행했다.

작은 합성 사례의 후보 1/8/32개 측정은 `benchmark.json`에 별도 보존한다. 실제 32층·120세대 형상, 다중 사용자 부하나 배포 성능의 증거는 아니다. 스트레스 실행 오류 UI의 브라우저 검사는 이 합성 계획에 BCR 준비 검사가 없어 진입하지 못했다. 이를 통과로 쓰거나 준비 검사를 우회하지 않았으며, 별도의 준비 완료 사례에서 실행/실패/재시도 시험이 필요하다. 최대 지원 규모의 성능·봉인 크기, 실제 원가/금융 독립 검산, 실제 운영 DB와 제품 인수는 후속 게이트다. 이 문서의 계산 연결 완료가 최종 Goal 완료를 뜻하지 않는다.
