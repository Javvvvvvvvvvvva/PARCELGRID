# Stage 2/3 Revenue Contract 2026.2

> 면적 풀과 `revenue-valuation-2026.2` 평가식은 현행이다. 단가 입력·출처·보정 계약은 [Revenue Pricing Contract 2026.3](REVENUE-PRICING-2026.3.md)이 이 문서의 공통 단가 규칙을 대체한다.

## 목적

Stage 2에서 사용자가 확정한 층별 용도와 매각·임대 전략을 Stage 3가 다시 추정하지 않도록 면적, 단가, 근거 상태와 잠금 매출을 하나의 계약으로 전달한다. 이 계약은 예비 타당성 계산의 재현성을 위한 것이며 감정평가, 임대차 조사 또는 투자 권유를 대체하지 않는다.

## 계약 버전

- 면적 계약: `stage2-finance-area-2026.2`
- 단가 스냅샷: `revenue-pricing-2026.2`
- 수익 평가식: `revenue-valuation-2026.2`
- Stage 2 개략 비용: `stage2-economics-preview-2026.2`

`stage2-finance-area-2026.1`은 읽기 호환만 유지한다. 새 대표안을 확정하면 2026.2 계약으로 다시 생성해야 하며, Stage 3 대표 대시보드는 현재 계약이 아니거나 계획 버전·Geometry Hash·면적이 달라지면 계산을 차단한다.

## 수익 풀

모든 수익 면적은 다음 여섯 풀 중 하나에만 속한다.

1. `residentialSale`: 주거 매각
2. `retailSale`: 상가 매각
3. `officeSale`: 업무 매각
4. `residentialLease`: 주거 임대
5. `retailLease`: 상가 임대
6. `officeLease`: 업무 임대

공용, 주차, 창고, 설비 공간 등 비수익 용도를 매각·임대로 지정하면 `unsupported-revenue-use` 실패로 대표안 확정을 차단한다. 수익 풀 합계는 `saleableAreaSqm + rentableAreaSqm`과 일치해야 한다.

## 평가식

매각 풀은 다음 식을 사용한다.

```text
매각가치(만원) = 면적(m2) x 매각단가(원/m2) / 10,000
```

임대 풀은 다음 식을 사용한다.

```text
잠재 연 임대료(만원) = 면적(m2) x 월 임대단가(원/m2) x 12 / 10,000
유효총수입(만원) = 잠재 연 임대료 x (1 - 공실률)
운영비(만원) = 유효총수입 x 운영비율
연 NOI(만원) = 유효총수입 - 운영비
임대가치(만원) = 연 NOI / Cap rate x 안정화 계수
```

현재 안정화 계수는 85%다. Stage 2와 Stage 3가 같은 공유 함수로 이 식을 실행하므로 동일 입력의 풀별 매출은 반올림 허용치 안에서 일치해야 한다.

## 현재 단가 규칙과 한계

- 주거·상가·업무 매각은 현재 하나의 `salePricePerSqM`을 공유한다.
- 주거·업무 임대는 현재 하나의 `rentPerSqMMonth`를 공유한다.
- 상가 임대는 공통 임대 단가에 내부 조정계수 1.2를 적용한다.
- 운영비율은 유효총수입 대비 20%를 내부 초기값으로 사용한다.
- 상가 1.2배와 안정화 85%는 시장 원문으로 확정된 값이 아니라 버전이 붙은 내부 예비 가정이다.
- 운영비 20%도 확정 운영예산이 아닌 내부 예비 가정이며 관리·수선·보험·공과금의 소유자 부담 자료로 교체해야 한다.
- 실제 의사결정 전에는 용도별 매각·임대 사례, 기준일, 위치·층·면적·신축 여부 보정과 전문가 확인이 필요하다.

검증된 가격 자료가 있으면 각 풀의 스냅샷에 `source-backed`, 출처명, 문서 참조와 기준일을 저장한다. 자료가 없거나 형식 검증에 실패하면 `internal-assumption`으로 남는다. 출처가 있다는 사실은 그 단가가 해당 용도에 적합하다는 전문가 판단까지 의미하지 않는다.

## Stage 2/3 대사

다음 항목을 각각 비교한다.

- 여섯 수익 풀의 면적·단가·매출
- 취득·철거비
- 직접 공사비
- 간접비
- 예비비
- 금융비
- 세전손익

동일 입력에서 수익 또는 공사비가 다르면 `fail`이며 계약을 재생성해야 한다. Stage 3에서 단가나 비용 가정을 명시적으로 변경한 차이는 `review`로 표시한다. Stage 2 금융비는 총사업비 비율 추정이고 Stage 3 금융비는 월별 PF 원장이므로 두 값의 차이는 정상적인 모델 정밀도 차이로 `review`한다.

`누적 자기자본 + PF 최고잔액 = 총사업비`는 회계 항등식이 아니다. 분양·매각대금 유입 시점, PF 상환과 재사용이 서로 달라 자금조달은 반드시 월별 원장으로 확인한다.

## 회귀 기준

- 혼합용도 계획에서 여섯 면적 풀이 Stage 2에서 Stage 3까지 보존된다.
- 업무 임대에는 상가 임대 1.2배가 적용되지 않는다.
- Stage 2와 Stage 3는 임대가치에 같은 85% 안정화 계수를 적용한다.
- 잠재 임대료, 공실 후 유효총수입, 운영비와 NOI 잠금값 중 하나를 변조해도 Stage 3 계산이 중단된다.
- 공용 공간을 매각 또는 임대로 표시해도 수익이 생성되지 않고 확정이 차단된다.
- 잠금 매출을 변조하면 Stage 3 계산이 중단된다.
- 계획 버전 또는 Geometry Hash가 달라진 계약은 Stage 3에서 사용하지 않는다.
- 검증된 가격 자료의 출처명, 참조와 기준일이 잠금 스냅샷에 보존된다.

## 후속 단가 계약

`revenue-pricing-2026.3`에서 여섯 풀 각각의 기준단가와 용도·입지·층·면적·신축 보정을 독립 입력으로 승격했다. 구형 공통 단가는 저장본 호환과 초기 fallback에만 사용한다.
