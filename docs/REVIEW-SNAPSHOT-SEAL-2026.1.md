# PARCELGRID 검토 Snapshot 봉인 계약 2026.1

기준일: 2026-09-09  
본문: `review-snapshot-2026.3`  
서버 봉인: `server-review-snapshot-2026.1`

## 봉인 대상

현재 대표 계획과 일치하는 Stage 3 저장본에서 다음 내용을 하나의 정규화 JSON으로
묶는다.

1. 프로젝트·대표 계획 ID와 버전, Geometry Hash
2. 계산 모델 버전과 Stage 3 계산 결과
3. 재무 입력 원문 메타데이터
4. 가격 검증 기록
5. 해당 계획의 안정화 매각·장기보유 세무 계약

저장·동기화 시각처럼 내용과 무관한 필드는 제외한다. 객체 키는 사전순으로
정렬하고 `undefined`는 제외한다. 같은 의미의 본문은 기기와 실행 순서가 달라도 같은
SHA-256을 가져야 한다.

## 서버 절차

서버는 프로젝트 일치, 대표 계획 존재, 모델 버전, Geometry Hash, 근거 묶음과 세무
계약 범위를 검증하고 정규화 UTF-8 본문 크기를 5MB로 제한한다. Web Crypto
SHA-256으로 `PG-REVIEW-SHA256-*` 키를 만든 뒤 본문 전체, 바이트 수와 키를 조직
감사 원장의 `review.snapshot_sealed` 이벤트로 저장한다. 같은 키의 중복 봉인은 기존
이벤트를 재사용한다.

검토 요청·시작·승인·수정 요청은 해당 조직과 프로젝트에 검증된 봉인 이벤트가
없으면 거부한다. 각 검토 이벤트는 Snapshot Key와 봉인 이벤트의 감사 해시를 함께
기록한다.

## 화면과 인계

인계 화면과 보고서는 현재 브라우저 계산에서 SHA-256을 다시 계산하고 서버 봉인
키와 일치하는지 조회한다. 값 하나라도 바뀌면 미봉인 상태가 되어 기존 승인을 최종
보고서에 사용할 수 없다.

서버 승인 기록은 수정 가능한 인계 JSON에 넣지 않는다. 다른 기기에서는 프로젝트
자료를 가져온 뒤 같은 조직 서버 원장에서 봉인과 승인 기록을 다시 읽는다.

## 경계

봉인은 승인 대상을 위변조 탐지 가능한 형태로 보존하지만 계산 자체의 법적 적합성,
원문 진위나 검토자의 법정 자격을 자동 보증하지 않는다. 공유 운영은 PostgreSQL
불변 트리거, 외부 신원 공급자와 필요한 전자서명 정책을 별도로 적용한다.
