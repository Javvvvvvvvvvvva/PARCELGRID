# 한국판 건축물대장 조회 근거

2026-09-28 · 내부 구획 업그레이드 다음 단계. 미국판 저장소는 변경하지 않는다.

## 사용 흐름

1. **새 부지 분석**에서 주소를 조회한다. Kakao의 정확한 지번으로 건축HUB 표제부를 요청한다.
2. 표제부 행을 확보하면 층별개요와 전유공용면적을 각각 조회한다. 어느 한 API의 실패가 확보된 다른 자료나 주소 등록을 지우지 않는다.
3. 새 부지 화면과 Stage 1 기존 건축물 패널의 **건축물대장 조회 근거**에서 조회 상태·건수·시각을 확인한다.
4. **층별개요 · 면적 대조**, **전유·공용 면적 원문**을 펼친다. 원본 PK·자료 생성일과 행별 면적(순번은 JSON)을 확인한다.
5. **대장 근거 JSON 저장**으로 보존한 전체 허용 필드, 조회 지번, 키가 없는 요청 URL, 대조 결과를 보관한다. 발급 대장 PDF나 도면 파일이 아니다.
6. Stage 3 결과를 다시 저장하면 해당 근거가 보고서 스냅샷에도 남는다. 보고서는 각 세부 자료의 첫 8행과 전체/수신 건수를 표시한다. 화면의 생략 행과 API 미수신 행은 서로 다른 상태다.

이전 저장 데이터에는 조회 메타데이터가 없을 수 있다. 이전 `hasBuilding: false`는 0건 확인으로 승격하지 않는다. 새 부지 분석에서 주소를 다시 조회해야 새 근거가 저장된다. 이미 저장된 대표 계획안에 최신 외부 자료를 자동으로 덮어쓰지 않는다.

## 상태 계약

| 상태 | 의미 | 허용하지 않는 해석 |
|---|---|---|
| 전건 확보 | 성공 헤더·페이지·명시적 전체 건수·수신 건수가 일치 | 현장 정확성·법적 적합성 보증 |
| 표제부 0건 | 해당 지번 요청의 정상 응답이 명시적으로 0건 | 실제 나대지 확정, 즉시 신축, 철거비 자동 제외 |
| 부분 조회 | 페이지 한도·후속 실패·중복·누락·건수 변경 등 | 전체 동수·전체 노후도·면적 대조 확정 |
| 실패·미설정 | 키/권한·HTTP·통신·응답 형식 오류 | 0건 또는 미등록 건물 없음 |
| 미조회 | 표제부 미확보 등으로 세부 호출을 실행하지 않음 | 세부 면적이 실제 0 |

GIS 건물 정보가 표제부와 다르면 GIS 관측값과 표제부 근거를 함께 보존한다. GIS 자료를 건축물대장 조회 성공으로 표시하지 않는다. 부속지번, 미등재, 멸실, 작성 시점 차이와 실제 현장을 별도로 확인한다.

## 공식 API와 조회 범위

[국토교통부 건축HUB 건축물대장정보 서비스](https://www.data.go.kr/data/15134735/openapi.do)의 공개 Swagger를 2026-09-28에 확인했다. 해당 페이지는 JSON/XML, 속성 제공 범위, PK 변경 안내, 이용허락범위 제한 없음 및 활용신청 조건을 안내한다. 상용 SDK나 연구 데이터·학습 가중치를 편입하지 않았고 신규 production 의존성도 없다.

| API | 보존·사용하는 자료 |
|---|---|
| `getBrTitleInfo` | 원본 PK, 동명, 면적·층수·용도·구조·사용승인, 주차 4항목, 승용/비상 승강기, 지붕 |
| `getBrFlrOulnInfo` | 원본 PK, 층구분·층명, 면적, 면적제외여부, 용도·구조, 생성일 |
| `getBrExposPubuseAreaInfo` | 원본 PK, 동·호·층, 전유공용 코드/명칭, 면적, 생성일 |

기존 `MOLIT_SERVICE_KEY`를 사용한다. 이 서비스에 대한 활용신청·승인도 필요하다. 키는 서버 요청에만 넣고 저장 결과·다운로드·오류 메시지에는 넣지 않는다. 소유자 API나 개인정보는 요청하지 않는다.

- `_type=json`을 명시한다. XML 형태의 게이트웨이 오류는 오류 코드만 해석한다. 예상하지 못한 성공 XML/HTML이나 필수 필드 누락을 0건으로 처리하지 않는다.
- API별 100행/페이지를 요청하고 응답 페이지 크기에 맞춰 순차 조회한다. 최대 10페이지·1,000행 및 API별 보존 행 JSON 350KB, 주 부지 조회 전체 25초, 개별 요청 8초 제한이다. 한도 도달 시 부분 조회로 보존한다.
- 주변 필지 조회는 표제부만 요청한다. 주변 필지마다 층별·전유공용 전체를 추가 호출하지 않는다.
- 동일 페이지 반복, PK·순번 중복, 표제부 PK 중복, 응답 건수 변경, 요청 지번과 다른 행을 검사한다. 문제가 있는 결과는 전체 면적 대조를 확정하지 않는다.
- 원본 PK를 다른 식별자로 변환하거나 구 PK → 신 PK 변환 규칙을 추측하지 않는다.
- 원문에 없는 숫자는 `null` 또는 `missingFields`로 구분한다. 기존 숫자형 계약의 0 호환값을 면적이 확인된 값으로 표시하지 않는다.
- `crtnDay`는 자료 생성일이다. 사용승인일·효력일·현장 확인일과 다르다. `retrievedAt`은 우리 조회 시각이며 UTC로 표시한다.

## 면적 대조와 재무

층별 행은 **표제부와 원본 PK가 정확히 같은 경우**에만 해당 동의 대조에 사용한다. 동명만 같거나 구/신 PK가 다르면 미연결 상태로 남긴다.

면적제외여부가 `N`인 행만 합산하고 `Y`는 제외한다. 면적 또는 제외여부가 미제공이면 대조 미완료다. 표제부와 층별 조회가 모두 완결돼야 차이를 계산한다. 차이가 0이어도 면적 산정의 법적 적합성·현장 일치를 승인하는 판정이 아니다.

전유공용은 원문 명칭이 확인된 전유/공용 행의 **수신 행 참고 합계**를 별도로 표시한다. 명칭이 없는 코드에 임의 의미를 부여하지 않는다. 호별 공용 배분과 대장 범위가 다를 수 있으므로 표제부 연면적과 단순 합산하거나 신규 구획의 매출·분양면적에 자동 반영하지 않는다. 기존 `연면적 ÷ 세대수` 참고값도 전유면적이 아니라고 표시한다.

주차대수는 옥내/외 기계식·자주식 네 항목이 모두 제공될 때만 합산한다. 누락과 0을 구분한다. 승용/비상 승강기 수는 중복 가능성을 고려해 별도로 표시한다.

대장 0건이나 `hasBuilding: false`만으로 총 취득대금에 토지 단독 취득세율을 적용하던 경로를 제거했다. 세율 변경이 아니라 적용 근거의 정정이다. 현장·계약·토지/건물 안분 입력이 없으므로 해당 취득세는 미산정이다. 세금 모델을 `tax-evidence-2026.2`로 기록하고, 이전 보고서·근거 패널의 세금 부분 추정값은 재저장을 안내한다. 신축 원시취득·법인세 등 기존 예비 계산 범위는 유지한다.

## 검증

```bash
pnpm verify
pnpm test:browser:registry
```

브라우저 검사는 프로덕션 빌드 후 실행한다. 기존 `pnpm test:browser`와 동일한 Playwright/로컬 Chromium 설정을 사용한다. 자체 임시 비밀번호로 로컬 서버를 실행하고 합성 자료만 브라우저 응답에 주입한다. API 키·DB 연결을 해당 검사 프로세스에서 비활성화하고 `test-results/building-registry`에 결과를 저장한다. 두 브라우저 스크립트나 빌드를 동시에 실행하지 않는다.

회귀 범위: 명시적 0건, 누락/손상 응답, 권한·호출한도·통신·시간 제한, 페이지 반복/한도/건수 변경, 단일 item, PK·주소·중복 검사, 숫자 누락과 실제 0, 세부 API 부분 실패, 면적제외/동일 PK 대조, 전유공용 분리, 키 없는 JSON·저장 용량 제한, 저장·동적 계산 경로, GIS와 대장 불일치, 취득세 오적용 차단.

현재 환경에는 MOLIT 키가 없어 **실제 승인 계정의 응답과 API별 권한은 검증하지 못했다.** 단위·브라우저 자료는 공식 필드 계약에 맞춘 합성 응답이다. 출시 전 승인된 계정에서 실제 다동·집합건물·0건·페이지 초과 사례를 확인하고, 제공기관의 생성/면적제외 코드가 누락된 경우 현재처럼 미확인으로 유지해야 한다.

최종 로컬 결과: `pnpm verify` 통과(95개 테스트 파일·407개 테스트·15개 페이지 production build), `pnpm repo:audit`에서 새 미참조 경로 없음. Chromium의 근거/면적 대조·JSON 저장·모바일·인쇄 스타일·부분/0건/권한 오류·이전 세금 값 재저장 안내 검사를 통과했고 페이지 오류는 0건이었다. 실제 승인 계정 검증과 A4 전체 보고서 수동 인쇄 확인은 별도다.
