# 주거 내부 수량과 원가 연결 계약

기준일: 2026-10-26, America/Chicago. 내부 구현 단계이며 전체 공종 견적·전문가 검산·제품 인수 완료가 아니다.

## 산출 범위

`quantity-takeoff-2026.2`는 저장된 원시 층·세대·실·문을 기존 실내/상세 실 검사에 통과시킨 뒤 집계한다. 최대 32개 층, 층당 20세대, 전체 120세대, 외곽 꼭짓점 128개이며 주거·공용부·주차·필로티 계획만 지원한다. 전체 상세 실 구획이 없거나 일부 충돌·누락이면 모든 합계는 `null`이다. 일부 합계를 전체 수량으로 표시하지 않는다.

| 수량 | 단위 | 정의와 제외 범위 |
|---|---|---|
| 내부 칸막이 | m | 세대 내부 실 사이 공유 선분의 합집합. 분할·T 접합·회전·중복 선분을 대사한다. 문 개구부 미공제 총길이이며 외벽·세대 둘레·공용부·코어 벽은 제외한다. |
| 실간 문 | 개 | 상세 실 사이 유효한 물리 개구부. 중복/역방향 사본은 한 번, 부분 겹침은 충돌. |
| 세대 현관문 | 개 | 실제 세대와 공용부 사이 개구부. 공용부끼리의 문과 상세 실에 복제된 현관 참조는 제외한다. 세대당 문 한 개를 가정하지 않는다. |
| 건식 바닥 | ㎡ | 벽 두께 가정을 차감한 욕실 외 실의 유효 바닥면적. 주방 포함, 공용부 제외. |
| 욕실 바닥 | ㎡ | 욕실 유효 바닥면적. 실제 방수 시공면적·벽 방수·시공 손실률은 아니다. |
| 주방·욕실 | 개 | 상세 실의 개수. 기구·연결설비 패키지의 견적 단위로만 쓰며 실제 배관 길이·기기 수량을 자동 산출한 것이 아니다. |

공식 경계, 현장 실측, 구조·외벽·공용부·전체 MEP·소방/방재 상세, 법정 피난 적합성, 허가 및 전문가 승인은 미확정이다. 저장된 `sourceOutline` 기반 수량 검사와 실제 Geometry 결속 검사는 별개다. 명시적 반영 시 현재 Geometry와 연결을 확인하고 통합 검토에서도 전체 원본 결속을 다시 검사한다.

## 포함액 교체 원칙

`quantity-cost-2026.1`에는 자동 시장 단가가 없다. 각 공종은 `unpriced`, `included`, `replace-allowance` 중 하나다. 기본은 미확정이며 빈 단가와 명시적인 0원은 구분한다.

- 기본단가 포함: 출처와 공종 범위 확인이 필요하며 별도 금액은 더하지 않는다.
- 포함액 차감 후 교체: `수량 × 견적 단가 - 기본 연면적 공사비 내 동일 공종 포함액`만 반영한다. 기존 포함액의 출처도 별도로 필요하다. 기존 포함액 총합은 기본 공사비를 초과할 수 없다.
- 기존 공사비와 동일한 부가세·노무비·재료비 기준 및 공종 포함/제외 범위를 사용자가 확인한다. `quoted`는 견적서 입력 상태일 뿐 원문 진위나 전문가 검산을 뜻하지 않는다.
- 주방/욕실 패키지는 바닥·벽체·문·공용 배관을 제외한다. 양수인 추가 세대 가산비가 남아 있으면 주방/욕실 교체 견적은 중복 위험으로 차단한다. 기존 가산비를 자동으로 0원 처리하지 않는다.
- 미지원 공종은 기본 연면적 단가에 남긴다. 세부 물량이 없다는 이유로 그 비용을 0으로 만들지 않는다.

합성 시험 예: 실제 모델 현관문 4개 × 테스트 단가 1,000,000원 - 기존 포함액 1,500,000원 = 2,500,000원(250만원) 증감이다. 이 숫자는 실거래·실제 견적·쌍문동 시장 단가가 아니다.

## 계산과 변경

사용자는 로컬 초안의 미리보기와 포함 범위를 확인한 뒤 명시적으로 반영한다. 반영 전에는 저장 계획·면적·수익·주차대수가 바뀌지 않는다. 미적용 단가 초안은 탭 이동/새로고침 후 보존을 보장하지 않으며, 반영한 계약은 기존 Workspace 저장·충돌·복구 경로를 따른다.

계약에는 전체 관련 원본 입력 기준, 정확한 지상·지하 면적, 채택 당시 기본 단가/배율, 수량·단가·포함액·출처를 저장한다. 평면·층고·면적·배치·관련 비용 가정이 바뀌면 재검토 상태가 된다. 이름/계획 버전/검사 캐시 변경만으로 수량을 바꾸지 않는다. 실제 원본과 계약 전체는 SHA-256 검토 봉인에 포함된다.

2026.2의 `sourceBasis`는 한도 검사를 거친 전체 관련 원본의 정규화 JSON을 SHA-256으로 계산한 버전 접두어 포함 지문이다. 원본 층·실·문 자료는 계획과 검토 자료에 그대로 보존하며 서버가 이를 다시 계산한다. 원본을 잘라내거나 검사 한도를 높이지 않는다. [noble-hashes](https://github.com/paulmillr/noble-hashes) 2.4.0의 SHA-256을 사용하고 Node 암호 구현과의 일치도 회귀 검사한다. 이전 2026.1 원문 문자열 기준 견적은 자동 변환하지 않고 stale로 처리한다. 저장값은 유지하고 새 초안 작성·범위 확인·미리보기·명시 반영이 필요하며, 이전 봉인과 승인을 새 검사 결과로 승계하지 않는다.

Stage 2 공사비는 `기본 공사비 + 외장 증감 + 추가 세대 가산비 + 상세 원가 증감`이다. 그 결과에 기존 설계비·예비비·금융비 가정을 적용한다. Stage 3는 같은 공사비를 월별 원장에 한 번만 전달한다. 단가·포함액의 원 단위를 유지하며 화면 표시 전 중간 반올림을 하지 않는다.

Stage 3 공사비 민감도에서는 교체된 공종을 다시 기본 단가로 증감하지 않는다:

```text
원가 증감 = 교체 견적액 - 기존 포함액 × (현재 기본 공사비 / 채택 당시 기본 공사비)
최종 공사비 = 현재 기본 공사비 + 원가 증감 + 외장 증감 + 추가 세대 가산비
```

즉, 상세 교체 견적액은 고정하고 기본 단가에 남은 공종 비율만 변동한다. 교체 견적 자체의 가격 위험은 새 단가 시나리오로 재검토해야 한다. 원래 기본 공사비 분모·정확 면적·채택 단가와 Stage 2 잠금 입력을 대사하며, 현재 민감도 단가와 과거 단가가 달라졌다는 이유만으로 민감도 실행을 막지 않는다.

사업성의 단가 민감도·절감 경로·스트레스는 위 범위를 명시한다. 보고서의 Low(-15%)/High(+20%)도 기본 공사단가를 변경한 월별 재계산으로 통합했다. 원가·금융비·자금 부족·세전 현금흐름을 함께 계산하며 고정 교체 견적을 일괄 증감하지 않는다. 계약과 최신 검증은 `CONSTRUCTION-COST-SENSITIVITY-2026.1.md`를 따른다. 구형 단순 범위는 재계산 전 표시하지 않는다.

오래된/불완전 원가의 사업성은 미확정이다. Stage 3 변환을 거부하고 계획 목록·사업성·추천의 이익 표시를 보류한다. 면적 반영 기능도 기존 원가를 암묵적으로 제거하거나 0원으로 비교하지 않는다. 사용자가 원가 반영을 명시적으로 해제하거나 현재 평면 기준으로 재작성해야 한다. 잠금 계획 변경은 데이터 계층에서도 차단하며 복제 시 원가 계약을 승계하지 않는다.

## 검토와 산출물

현재 `review-snapshot-2026.6`, `integrated-verification-2026.3`이 원시 수량·원가와 Stage 3 계약 및 월별 민감도·비교 순위를 다시 대사한다. 서버는 클라이언트의 검사 결과를 믿지 않고 재계산한다. `null`/빈 문자열을 0으로 바꾸지 않으며 기존 세대·재료 증감도 원시 계획과 대조한다. 인계·보고서·JSON 다운로드에 같은 수량·단가·출처·키가 표시된다.

2026.5 이하 검토 기록은 이력에 남지만 현재 검사 계약의 승인으로 승계하지 않는다. 새 봉인과 검토가 필요하다. 전체 공종 물량과 독립 견적 검산은 아직 `missing`으로 남아 시행·재무 승인을 차단한다. 지원 수량 계산 성공을 전체 BOQ 완료나 법적 승인으로 승격하지 않는다.

## 내부 검증

전용 회귀는 손계산 평면, 공유 선분 중복, 회전, 문 사본/중첩, 미지원/범위 한도, 원가 중복, 근거 누락, stale, 조작된 계약, 민감도, Stage 2/3와 Workspace·봉인 연결을 포함한다. 내부 합성 회귀는 독립 실무자 검산의 대체물이 아니다.

브라우저 증빙: `artifacts/quantity-cost-2026-10-26/`. 격리한 합성 프로젝트와 테스트 단가로 미리보기/명시 반영, 확인 무효화, 새로고침 복구, 형상 변경 무효화, 삭제, 실제 서버 봉인, 인계/보고서 동일 키, PC/모바일을 검사한다. 실제 고객 Workspace를 덮어쓰지 않는다.

최종 내부 실행 결과: `pnpm verify`의 테스트 985개 통과, PostgreSQL 통합 1개 제외, ESLint·TypeScript·production build 통과. 전용 수량 50개·원가 28개·원가 결속 45개를 포함한다. 실제 합성 브라우저 봉인 시험과 1440px/390px 화면 검사에서 page error·가로 넘침은 없었다. 독립 코드 검토가 지적한 기준 분모 조작, 이전 계산 결과 재사용, null/문자열 수치 강제변환, 기존 세대 가산비 불일치를 수정·회귀 검증했다. 실제 DB/전문가/제품 인수는 미완료다.

남은 외부 과제: 실제 도면 10건의 물량 대조, 공종별 실제 견적과 포함액 근거 확보, 시공/QS 전문가 독립 검산, 구조·공용부·MEP·방재 상세 모델 확장. 사용자 승인이 필요한 자료 제공·유료 외주·계약은 임의 실행하지 않는다.

후속 최대 규모 검증은 `artifacts/scale-validation-2026-10-26/`를 따른다. 합성 32층·120세대의 원문 중복 연결값 때문에 통합 검사에서 한도 초과하던 결함을 재현·수정했다. 모든 7종 수량의 반복층 비례, 원본 보존, 마지막 세대 변경 감지, 32개 재무 비교안의 실제 서버 봉인/중복/변조 거부 및 구형 견적 재반영 UI를 확인했다. 이는 32개 대안 각각의 상세 평면·최대 꼭짓점·운영 부하·법적 허용 규모 인수가 아니다.
