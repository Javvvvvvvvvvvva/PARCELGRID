# 한국판 내부 구획·일영 업그레이드

2026-09-28 · 한국 PARCELGRID의 첫 기능 묶음. [전체 리소스·후속 계획](KR-UPGRADE-RESOURCES-2026-09-28.md).

## 사용 방법

1. 계획 스튜디오에서 편집할 계획안을 선택한다. 잠긴 형상은 기존 형상 출처 패널에서 먼저 해제한다.
2. 매스 아래 **내부 구획 열기**를 누르고 층을 선택한다.
3. 세대 수·코어/복도·최소 내부 폭/면적·벽 두께를 입력하고 후보를 생성한다. 이 값은 사용자 가정이며 법규 최소값이 아니다.
4. 후보를 적용하거나 공간을 추가한다. 2D에서 끌기, 수치 편집, 회전, 잠금, 되돌리기를 사용할 수 있다. 새 후보 적용은 현재 구획 전체를 교체한다.
5. 맞닿은 공용 공간의 문을 배치한다. 개별 공간 사이의 문은 공간을 선택해 연결하고 폭을 조정한다. 모서리 접촉만 있는 공간끼리는 연결되지 않는다.
6. 공간 관계 탭에서 인접·분리 선호를 연결한다. 미충족 선호는 검토 항목이며, 관계선을 추가한다고 이미 배치된 공간이 자동 이동하지 않는다.
7. 경계 침범·겹침·최소 치수·문 위치·코어 연결 검사를 통과한 후 **사업성 면적에 반영**한다.
8. 내부 DXF 패키지 또는 Rhino 3DM 구획을 내보낸다. 독립적인 개념 구획 인계 파일이며 기존 외부 매스 DAE/DXF의 벽체 상세를 추가하는 기능은 아니다.

지하층도 수동 검토할 수 있으나 현재 자동 후보는 주거 세대 템플릿이다. 지하 주거의 허용 여부나 주차 경로를 판정하지 않는다. 층 변경으로 외곽이 달라지면 현재 외곽에 구획을 다시 대조해야 한다.

## 실제 구현 범위

- 최대 12세대 자동 후보, 층당 최대 64개 수동 공간·128개 문·256개 관계.
- 최장 변을 기준으로 두 방향을 시도하고 좌측/우측/중앙 공용 동선과 세대 띠를 구성한다. 오목한 외곽에서는 완전히 포함되는 격자 직사각형을 찾는다.
- 후보는 기하 검사를 통과한 것만 제시하고 추정 분양 내부 면적 비율로 정렬한다. 전역 최적해·수익 최적해를 보장하지 않는다.
- 코어·복도·주거 세대와 수동 거실·침실·주방·욕실·상가·창고의 직사각 구획을 지원한다. 세대 내부의 방 배치를 자동 완성하지 않는다.
- 공간은 단일 계층이며 방을 세대로 자동 묶지 않는다. 용도를 방으로 바꾸면 세대 수 기본값은 0이다. 방 단위로 편집하는 사용자는 같은 세대의 세대·실 수를 한 구획에만 명시한다.
- 3D는 같은 구획과 문 개구 위치를 표시하는 공간 블록 미리보기다. 벽체 솔리드·창호·문 회전·가구·계단 상세·설비 모델은 아직 없다.
- 계산은 Comlink Worker에서 수행한다. 취소·30초 제한·계획 변경 시 이전 결과 폐기를 지원한다.

## 면적·사업성 계약

구획 다각형은 가정한 벽 중심선이다. 내부 면적은 폭과 깊이 각각에서 가정 벽 두께를 한 번 뺀 값의 곱이다. 인증된 전용면적·분양면적이 아니다.

- 기존 층 프로그램 총면적을 보존한다. 아주 작은 부동소수점 초과는 공용 구획에서 조정한다.
- 미배치 면적은 비수익 공용 영역으로 남긴다. 공용 코어·복도는 매출과 세대 수에 포함하지 않는다.
- 사용자가 선택한 분양/임대 구획의 추정 내부 면적만 해당 수익 면적에 반영한다. 공사비의 층 총면적을 순면적으로 바꾸지 않는다.
- `interiorFinanceSignature`는 마지막으로 함께 반영한 구획과 재무 구역 입력을 기록한다. 내부 형상이나 기존 정밀 편집의 수익 구역을 바꾸면 재반영 전 대표안 확정과 기존 확정안 내보내기를 차단한다.
- 내부 평면도와 3DM은 기하 검사 통과 후 개념 검토용으로 먼저 내보낼 수 있다. 사업성 검증을 통과한 확정 보고서라는 뜻은 아니다.
- 신규 내부 필드가 없는 기존 계획의 형상 해시 입력은 유지한다. 내부 구획이 있는 계획은 구획 변경도 Geometry Hash에 반영한다. 복제 시 구획은 깊은 복사한다.

## 좌표·출력 계약

| 항목 | 화면·계산 | DXF·3DM |
|---|---|---|
| 길이 | meter | meter |
| 동 | +X | +X |
| 북 | -Z | +Y |
| 높이 | +Y | 3DM +Z, DXF 해당 층의 2D 도면 |
| 기준 | 기존 PlanningGeometry WGS84 원점 | 같은 원점을 메타데이터에 보존 |

DXF ZIP에는 레이어 분리된 도면, `metadata.json`, UTF-8 안내문이 들어간다. 한글은 DXF Unicode escape로 저장한다. 3DM에는 층 외곽·공간 중심선·추정 내부 경계·문 개구 곡선과 객체 이름을 담는다. 문 선은 개구 위치이며 상세 문틀이 아니다.

## 예비 일영

SunCalc 2.0.2의 도 단위·북 기준 방위각을 사용한다. 기존 1.x의 라디안/남 기준 수식과 혼용하지 않는다.

- 한국 표준시(UTC+09), 입력 날짜와 시간 범위, 30분 간격 중간 시각의 태양 위치를 사용한다.
- 부지의 12×12 격자 중 계획 건물 아래를 제외한 외부 지면에서 BVH 광선 교차를 계산한다.
- 각 구간 중간 시각의 차폐 여부를 그 구간 전체에 적용한 근사 시간이다. 마지막 구간은 남은 분만 더한다.
- **계획 매스만 포함한다.** 주변 건물·지형·기상·실내·창호·반사광은 미포함이다. 법정 일조 적합성이나 채광 성능 지표가 아니다.
- 형상·날짜·시간이 바뀌면 이전 결과를 제거한다.

## 자산·라이선스

새 production 의존성: React Flow(MIT), Comlink(Apache-2.0), SunCalc(BSD-2-Clause), three-mesh-bvh(MIT), rhino3dm(MIT). 기존 Turf·Drei·Three를 재사용한다.

`pnpm dev`와 `pnpm build`의 사전 작업이 설치된 고정 버전의 Rhino JS/WASM/고지를 `public/vendor/rhino3dm`에 복사한다. 해당 생성 폴더를 수동 수정하거나 커밋하지 않는다. 새 런타임 자산의 외부 CDN 호출은 없다.

기존 매스·도로 3D 라벨은 Drei Html과 브라우저 글꼴을 사용한다. 외부 폰트 서버가 막히면 라벨 작업이 실패하던 Troika 텍스트 경로를 제거했다.

`pnpm notices:generate`로 [배포 고지](../public/third-party-notices.txt)를 갱신한다. 라이선스 판정과 실제 채택 상태는 [리소스 목록](kr-upgrade-resources.json)에 기록한다. 제한된 연구 코드·가중치·데이터를 변형하여 포함하지 않았다.

기존 sharp 보정 버전은 0.35.4로 갱신했다. [GHSA-rgj7-g3m4-5g8c](https://github.com/advisories/GHSA-rgj7-g3m4-5g8c)의 수정 버전이며, 기존 production audit 검사를 유지한다.

## 검증과 남은 확인

이번 로컬 결과: `pnpm verify` 통과(93개 파일·380개 테스트·15개 페이지 빌드), production audit에서 알려진 취약점 0건. Chromium에서 아래 전체 흐름을 실행했고 페이지 오류는 0건이었다. 브라우저에서 받은 DXF는 별도 ezdxf reader로 재검사하여 오류 0건·자동 수정 0건, meter와 한글 라벨을 확인했다. native 3DM은 저장 후 재읽기에서 레이어·높이·단위·원점·해시를 대조했다.

기본 Plan Studio 라우트의 빌드 크기는 이 환경에서 396KB → 362KB였다. 새 그래프·3D 구획·Rhino 내보내기는 필요할 때 로드한다. 새로고침 시 Next의 사용하지 않는 페이지 사전 요청이 취소되는 로그는 페이지 오류와 분리해 기록한다.

자동 검증: 회전/오목 외곽, 침범·겹침·공유 변·문 연결, 잘못된 입력, 후보 미발견, 사업성 재반영, 총면적 보존, 깊은 복사·잠금, DXF 메타데이터, native 3DM 저장/재읽기, 태양 좌표축·KST·야간·그림자·구간 시간 대사.

```bash
pnpm verify
pnpm audit --prod --audit-level high
pnpm repo:audit
```

실제 Chromium 검사(Playwright 1.62.1 개발 의존성):

```bash
pnpm exec playwright install chromium
pnpm build
pnpm test:browser
```

검사 스크립트는 127.0.0.1:3100에 임시 비밀번호를 쓰는 로컬 프로덕션 서버를 띄운다. 데모 구획 생성·범위 밖 편집·되돌리기·사업성 동기화·관계 연결·2D/3D·DXF/3DM 다운로드·일영·새로고침 저장 복원을 확인하고 `test-results/interior`에 검사 파일을 남긴다. 실제 API 키와 DB 연결은 해당 검사 프로세스에서 비활성화한다. 프로덕션 빌드와 브라우저 검사를 동시에 실행하지 않는다.

수동 출시 조건: Windows의 Rhino/AutoCAD 호환 프로그램에서 meter·한글·층 높이·레이어 확인, 실제 건축가의 코어·문·계단·피난 검토. 자동 검증만으로 허가·시공용 도면 완성도를 주장하지 않는다.
